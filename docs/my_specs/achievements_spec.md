- **Обзорные уроки** не участвуют в сериях по стихам и тестам (ДС-15).
- Алгоритм пересчёта и логическая модель данных (раздел 7), каталог прототипа (раздел 9).

## 1. Цель и принципы

Достижения фиксируют **вехи** — постоянство, старание, память. Каждое достижение несёт баллы (pointsValue), и ребёнок получает за них кирпичики (БП-11 основной спецификации). Чтобы это не превратилось в самоподдерживающуюся систему очков, действует ДС-10: баллы достижений **не участвуют в правилах достижений**.

Принципы (обязательны при реализации):
- награждается усилие и постоянство, а не «быть лучшим»;
- **никаких автоматических потерь:** достижение не отбирается автоматически, серия не «сгорает». Единственное исключение из «никаких штрафов» — штраф за поведение, который учитель выдаёт вручную, с причиной и возможностью снять (раздел 6);
- **никаких публичных рейтингов детей** (Раздел 8 основной спецификации);
- мало достижений: на первый год 8–12, три категории — постоянство, старание, память; больше — обесценивание;
- уровни (бронза / серебро / золото) вместо множества похожих бейджей;
- **одни и те же действия награждаются одним достижением каждого уровня один раз** (ДС-3);
- живой момент остаётся за учителем: система подсказывает, кого отметить, — объявляет учитель в классе.

## 2. Каталог (Achievement)

Ведёт admin. Одна запись каталога — либо **достижение** (pointsValue ≥ 0), либо **штраф** (pointsValue < 0, раздел 6). Вид задаётся при создании и не меняется после первой выдачи.

Поля достижения:
- код, название и описание на RU и EN, иконка;
- категория (постоянство / старание / память);
- **тип правила** и его параметры: метрика, порог, длина серии (раздел 3);
- уровни (бронза / серебро / золото): у каждого своя длина серии или число раз и свои баллы;
- **баллы за уровень (pointsValue)** — целое ≥ 0. При ручной выдаче учитель может указать меньше, но не больше значения каталога (с причиной, в журнал);
- активно / отключено.

Изменение чисел и текстов — в каталоге, без изменения кода. Код реализует **ограниченный набор типов правил**, а не произвольный движок правил. Изменение порога, длины серии или баллов действует только на будущие выдачи; уже выданное не пересчитывается. В каждой выдаче хранится снимок параметров правила на момент выдачи — чтобы «за что» оставалось объяснимым после правки каталога.

## 3. Типы правил и факты

**Факт** — одна проверенная запись ученика на уроке (HomeworkCheck), оценённая по метрике правила. Для каждого правила факт бывает в одном из трёх состояний:

| Состояние | Когда | Влияние на серию |
|---|---|---|
| **засчитан** | метрика оценена и не ниже порога | продлевает серию |
| **не засчитан** | метрика оценена и ниже порога | обрывает серию |
| **пропуск** | урок не подходит (ДС-2, ДС-14, ДС-15) или метрика «не оценивалась» | не продлевает и не обрывает |

Типы правил:
1. **Серия.** Засчитанные факты подряд (пропуски не считаются). Уровень = длина серии. Пример: тетрадь от 9 баллов на 3 / 5 / 10 уроках подряд.
2. **Накопление.** Число засчитанных фактов за учебный год. Пример: уроки с выполненным ДЗ — 5 / 15 / 30.
3. **Разовое событие.** Первый засчитанный факт в учебном году. Пример: первый стих на «2».

Метрики берутся в том виде, как они определены в БП-2…БП-4 основной спецификации. «Стих выучен» по умолчанию — оценка 2; порог параметризуется. Метрики считаются **только по компонентам оценок урока** (стихи, тест, тетрадь, спевка, факт выполнения ДЗ); баллы за достижения в метриках не участвуют (ДС-10).

Серия по «посещаемости подряд» **сознательно не предлагается**: она противоречит прощающей серии (ДС-1). Посещаемость поощряется накоплением.

## 4. Правила

**ДС-1 Прощающая серия (решение владельца).** Пропуск урока **не обрывает серию**. Серию обрывает только оценённый факт ниже порога.

**ДС-2 Подходящий урок.** Урок подходит для правила, если он проведён, проверка по нему завершена и метрика правила **оценена**. **Присутствие значения не имеет** (БП-10): ученик мог отсутствовать и сдать задания позже.
- Отменённый урок (событие календаря, урока нет), урок без записи проверки, урок, где метрика «не оценивалась», — пропуск.
- Для стихов факт определяется оценкой **на момент закрытия окна** (ВП-8). Стих, выученный позже (ВП-16), не достраивает серию задним числом, но идёт в накопительные достижения.

**ДС-3 Одни и те же действия — одна награда (изменено).** Один факт может быть использован **не более одного раза для каждой пары «достижение + уровень»**. Это гарантируется не кодом, а ограничением уникальности данных (ДС-12): повторная выдача за те же уроки невозможна даже при ошибке в коде или одновременных пересчётах. Повторный пересчёт ничего не меняет. Штрафы (раздел 6) — исключение: они выдаются вручную, ограничение — ШТ-4.

**ДС-4 Объяснимость.** Каждая выдача хранит **доказательства** — список фактов (уроков), на которых она основана, и снимок параметров правила. Учитель и родитель видят «за что»: «Аккуратная тетрадь · бронза — за уроки 06.09, 13.09, 20.09».

**ДС-5 Источник выдачи.** Каждая выдача имеет источник «автоматически» или «вручную». Для ручной выдачи обязательны: кто выдал, причина, количество баллов (не больше значения каталога) и — для достижений с правилом — доказательства (ДС-13). Teacher выдаёт вручную в своих группах, admin — в любых.

**ДС-6 Когда считать (по событию, а не по расписанию).**
- Основной триггер — **«проверка урока завершена»**: пересчёт для учеников этого урока, результат сразу.
- Дополнительные: правка проверенного урока (БП-12) — пересчёт для этого ученика; закрытие окна голосовой практики (ВП-8); закрытие учебного года (БП-6); включение режима достижений (ДС-14).
- Кнопка «Пересчитать» у admin — на случай правок задним числом.
- Плановый периодический пересчёт по всей базе **не является основным механизмом**: данные меняются раз в неделю.

**ДС-7 Отзыв (изменено).** Автоматически достижения не отзываются, даже если запись задним числом исправили в меньшую сторону. Отозвать может только admin — с причиной и записью в журнал (БП-8). Отзыв снимает баллы (ДС-10), **но доказательства остаются занятыми**: иначе следующий пересчёт выдал бы то же достижение за те же уроки, и отзыв отменил бы сам себя. Отзыв окончателен: за эти уроки это достижение этого уровня больше не выдаётся. *Подтвердить — Раздел 12.2 п. 11 основной спецификации.*

**ДС-8 Уведомления.** Новые достижения попадают в еженедельный дайджест родителю. Учителю после завершения проверки показывается список «кого сегодня отметить» — только выдачи этого пересчёта.

**ДС-9 Двуязычность.** Названия и описания хранятся на RU и EN; показываются на языке интерфейса пользователя.

**ДС-10 Баллы за достижения и защита от петли.**
- Выдача начисляет баллы уровня **один раз** и учитывается в «набрано» (БП-11) того учебного года, в котором выдана.
- Баллы достижений показываются **отдельной строкой «бонус»**.
- Баллы достижений **не входят** ни в метрики правил, ни в рейтинг по умолчанию (РТ-3).
- Отзыв снимает баллы; остаток кирпичиков может стать отрицательным (БП-11).
- Изменение pointsValue в каталоге **не пересчитывает** уже выданное.

**ДС-11 Серия и уровни (решение владельца).** **Одна серия — одна награда каждого уровня.** Серия — непрерывная цепочка засчитанных фактов; пропуски её не рвут (ДС-1), рвёт только факт ниже порога. Если серия дошла до 3, ребёнок получает бронзу, до 5 — серебро, до 7 — золото (длины — из каталога), **каждую по одному разу**. После обрыва начинается новая серия, и за неё уровни можно получить снова.
- **Та же серия или новая.** Серия считается уже награждённой уровнем *t*, если у ученика есть выдача этого достижения уровня *t* (в том числе отозванная или ручная), доказательства которой **пересекаются** с этой серией. Пересечение = та же серия.
- **Почему не «ключ по первому уроку серии».** Правка задним числом (БП-12) может сдвинуть начало серии на урок раньше; ключ изменится, и ребёнок получит вторую награду за те же действия. Пересечение доказательств этому устойчиво.
- **Слияние серий.** Если правка задним числом соединила две награждённые серии в одну, обе выдачи остаются (ДС-7), новых не появляется.
- **Накопление и разовое событие** не повторяются: каждый уровень — не более одного раза за учебный год. Защита — уникальность «ученик + достижение + уровень + учебный год».

**ДС-12 Доказательства (решение владельца).** Каждая выдача (автоматическая или ручная) **занимает** факты: для серии — первые N фактов серии, где N — длина уровня; для накопления — первые N засчитанных фактов; для разового события — один факт. Пара «достижение + уровень + факт» уникальна. Занятый факт остаётся занятым после отзыва (ДС-7) и после правки оценки в любую сторону.

**ДС-13 Ручная выдача с доказательствами (решение владельца).** Для достижения с правилом учитель отмечает уроки, за которые выдаёт награду. Система **предлагает последние подходящие** (засчитанные и не занятые для этого уровня) и проверяет:
- отмечено не меньше N уроков, где N — длина серии или число раз для уровня;
- ни один отмеченный урок не занят этим достижением этого уровня;
- уроки, которые автоматика считает «не засчитан», отметить можно — это и есть случай, когда автоматика не права; причина обязательна.

Ручная выдача занимает отмеченные уроки так же, как автоматическая, поэтому следующий пересчёт не выдаст то же самое второй раз. Достижения без правила (если появятся в каталоге) выдаются без доказательств.

**ДС-14 Режим достижений группы (решение владельца).** В настройках группы на учебный год есть переключатель **«Достижения и штрафы»**. Включает и выключает teacher своей группы или admin; каждое переключение — запись в журнале с датой.
- **Выключен:** автоматический пересчёт не запускается, ручная выдача достижений и штрафов недоступна, список «кого отметить» не показывается.
- **Уже полученные достижения не удаляются** и не отзываются, их бонусы остаются в «набрано» кирпичиков; штрафы сохраняются и могут быть сняты. Ребёнок и родитель по-прежнему видят историю.
- **Уроки, проведённые, пока режим был выключен, — пропуск** для всех правил: не засчитываются и не обрывают серии. Иначе включение режима выдало бы пачку наград «за прошлое», которое никто не обещал награждать.
- **Включение** запускает пересчёт для учеников группы — по урокам до выключения и после включения.
- История включений хранится периодами (с какой даты по какую режим был выключен) в настройках группы.
- По умолчанию режим включён. При создании нового учебного года копируется вместе с остальными настройками.

**ДС-15 Обзорные уроки (решение владельца).** На обзорном уроке (3.11 основной спецификации) не задают золотые стихи, не пишут тест и не рассказывают стихи; оцениваются тетрадь и спевка.
- Для правил по **стихам и тесту** обзорный урок — **пропуск**: не продлевает и не обрывает серию.
- Для правил по **тетради** обзорный урок — обычный факт.
- Для накопления «уроки с выполненным ДЗ» обзорный урок засчитывается, если оценена тетрадь.
- **Спевка — отдельное событие, а не часть урока:** её отмечают на любом уроке, включая обзорный. Для правила по спевке обзорный урок — обычный факт.

## 5. Сценарии (проверка правил на примерах)

Достижение «Аккуратная тетрадь»: тетрадь от 9; бронза — 3, серебро — 5, золото — 10 уроков подряд. З — засчитан, Н — не засчитан, П — пропуск.

| Уроки | Что выдано | Почему |
|---|---|---|
| З З З | бронза (уроки 1–3) | серия длиной 3 |
| З З З З З | бронза (1–3), серебро (1–5) | одна серия, каждый уровень один раз; вторая бронза за уроки 4–5–… не выдаётся |
| З З П З | бронза (1, 2, 4) | пропуск не рвёт серию |
| З З З Н З З З | бронза (1–3), бронза (5–7) | урок 4 оборвал серию; новая серия — новая бронза |
| Урок 4 исправили с Н на З | серебро (1–5) | серия 1–7 пересекается с обеими бронзами — новой бронзы нет; серебра у этой серии ещё не было, длина 7 ≥ 5 |
| Бронзу (1–3) отозвали, пересчёт | ничего нового | уроки 1–3 остаются занятыми |
| Учитель вручную выдал бронзу за уроки 6–8, затем завершил проверку урока 9 | только новые уровни, если серия их достигла | уроки 6–8 заняты ручной выдачей |

*В строке с исправлением урока 4 видно важное следствие: правка вверх может выдать **следующий уровень** той же серии. Это правильно — ребёнок действительно сделал 7 уроков подряд.*

## 6. Штрафы (анти-достижения)

**Назначение.** Зафиксировать серьёзное нарушение на уроке (например, плохое поведение) так, чтобы у него было последствие в той же «валюте», что и у наград, — в кирпичиках. Это сознательное исключение из принципа «никаких штрафов», поэтому штраф огорожен правилами ниже: инструмент учителя, а не автоматика и не публичное наказание.

**ШТ-1 Каталог.** Штраф — запись каталога вида «штраф»: код, название и описание на RU и EN, **pointsValue < 0**, активно / отключено. Категории, уровней и типа правила нет. Ведёт admin. Стартовый каталог — раздел 9.2.

**ШТ-2 Только вручную.** Штраф никогда не выдаётся автоматически и не вычисляется из оценок: низкий балл, пропуск или невыученный стих — не повод для штрафа. Выдаёт teacher своей группы или admin, только при включённом режиме достижений (ДС-14).

**ШТ-3 Обязательные поля.** Ученик, урок (по умолчанию — текущий), вид штрафа, баллы, причина. Причину видит родитель, поэтому интерфейс подсказывает писать о поступке, а не о ребёнке.

**ШТ-4 Размер и частота.** Учитель может уменьшить штраф по модулю, но не больше значения каталога. У ученика не более одного действующего штрафа за урок. *Подтвердить — 12.2 п. 19 основной спецификации.*

**ШТ-5 Что штраф меняет, а что — нет.** Уменьшает «набрано» кирпичиков за учебный год (отдельная строка «штрафы»). **Не** меняет: баллы и оценки урока; аналитику успеваемости и динамику; факты и серии достижений; выданные достижения; место в рейтинге (число штрафов — отдельной колонкой).

**ШТ-6 Остаток.** Физически выданные кирпичики не забираются; отрицательный остаток гасится будущими баллами (БП-11).

**ШТ-7 Снятие («простить»).** Штраф не редактируется и не удаляется — его снимают: статус «снят», кто, когда, почему. Баллы возвращаются. Teacher снимает в своих группах в активном году, admin — в любом. Родитель видит снятый штраф как снятый, с причиной.

**ШТ-8 Видимость.** Видят teacher своей группы, admin, parent своего ребёнка. Не появляется: в «кого отметить», на проекторе, у других родителей. Родитель узнаёт из еженедельного дайджеста.

**ШТ-9 Журнал.** Выдача, изменение и снятие — записи журнала изменений.

**ШТ-10 Учебный год.** Штраф принадлежит году урока; после закрытия года снять может только admin.

**Маркировка в интерфейсе.** Штрафы отмечаются **тёмно-синим** (токен `penalty`) с иконкой флажка и словом «Штраф»; кнопка выдачи штрафа — того же цвета. Красный остаётся за ошибками и удалением (DESIGN_SYSTEM.md).

## 7. Алгоритм пересчёта и логическая модель

### 7.1 Логическая модель (ориентир для схемы БД)

```
achievement            — каталог (ДС-…, ШТ-1): kind = reward | penalty, rule_type, metric, threshold, active
achievement_tier       — уровни: achievement_id, tier, length (N), points
achievement_award      — выдача: pupil_id, achievement_id, tier, academic_year_id, points,
                         rule_snapshot, source (auto | manual), awarded_by, reason, awarded_at,
                         revoked_at, revoked_by, revoke_reason,
                         award_key — только для накопления и разового события:
                                     «ученик + достижение + уровень + год», уникален (ДС-11)
achievement_evidence   — доказательства: award_id, achievement_id, tier, fact_id (запись проверки);
                         уникальность (achievement_id, tier, fact_id) — ДС-3, ДС-12
penalty                — выданный штраф: pupil_id, achievement_id (kind = penalty), lesson_id, points,
                         reason, issued_by, issued_at, cancelled_at, cancelled_by, cancel_reason;
                         не более одного действующего на (pupil_id, lesson_id) — ШТ-4
grade_settings         — + achievements_enabled и периоды выключения (ДС-14)
```

Ученик в доказательствах не дублируется: факт (запись проверки) уже принадлежит одному ученику на одном уроке.

### 7.2 Пересчёт для одного ученика

1. Транзакция; блокировка на уровне ученика (например, `pg_advisory_xact_lock(pupil_id)`), чтобы два пересчёта одного ученика шли строго по очереди.
2. Загрузить факты ученика за учебный год по дате урока и все его выдачи (включая отозванные) с доказательствами.
3. Вызвать **чистую функцию** `evaluate(facts, rules, awards) → новые выдачи`:
   - **серия:** найти максимальные серии (засчитанные подряд, пропуски игнорируются). Для каждой серии длины L и каждого уровня с N ≤ L: если нет выдачи этого достижения и уровня, доказательства которой пересекаются с серией, — новая выдача, доказательства = первые N фактов серии;
   - **накопление:** если засчитанных фактов не меньше N и нет выдачи этого уровня в этом году — новая выдача, доказательства = первые N засчитанных фактов;
   - **разовое событие:** первый засчитанный факт, если выдачи в этом году нет.
4. Записать выдачи и доказательства. Нарушение уникальности — пропустить выдачу (страховка от гонок и ошибок).
5. Вернуть новые выдачи — это список «кого отметить».

Состояние факта (засчитан / не засчитан / пропуск) вычисляет отдельная функция по метрике, с учётом ДС-2, ДС-14 и ДС-15.

**Neon.** Пересчёт требует интерактивной транзакции. HTTP-режим драйвера Neon выполняет только пакет запросов разом; для пересчёта нужен Pool / WebSocket-клиент или обычный драйвер `pg`. Проверить при выборе ORM.

### 7.3 Обязательные тесты `evaluate`

- **Идемпотентность:** повторный вызов на тех же данных не даёт новых выдач.
- **Независимость от порядка событий:** пересчёт после каждого урока и один пересчёт в конце дают одинаковый набор выдач.
- **Правка задним числом** (сдвиг начала серии, слияние двух серий) не создаёт дубль того же уровня.
- **Отзыв:** после отзыва пересчёт не выдаёт то же достижение.
- **Ручная выдача:** после ручной выдачи за уроки X пересчёт не выдаёт тот же уровень за серию, содержащую X.
- **Обзорный урок** между двумя засчитанными уроками по стихам не обрывает и не продлевает серию; по тетради — продлевает.
- **Режим выключен:** уроки периода выключения — пропуск.

### 7.4 Почему не другие подходы

- **Вычислять достижения на лету, без хранения выдач:** выдача начисляет физические кирпичики; если после правки данных достижение «исчезнет», журнал кирпичиков разойдётся с реальностью. Выдача — неизменяемый факт.
- **Ключ серии по первому уроку:** ломается правками задним числом (ДС-11).
- **Ежедневный фоновый пересчёт:** не нужен при событиях раз в неделю и задерживает бейдж.
- **Event sourcing:** избыточно для одной школы; доказательства дают ту же проверяемость.

## 8. Аналитика и права (сводка)

- **Права:** каталог — admin; ручная выдача — teacher своих групп и admin; отзыв — только admin; штраф и снятие штрафа — раздел 6; режим достижений — teacher своей группы и admin (ДС-14).
- **Метрики** (Раздел 9.4 основной спецификации): выдано за период по категориям и уровням; доля ручных выдач (рост — сигнал, что правила не совпадают с ожиданиями учителей); дети без единого достижения за N уроков; штрафы по видам и учителям, доля снятых; дети с двумя и более штрафами за месяц.

## 10. Решения по открытым вопросам (10 октября 2026)

Все вопросы закрыты.

1. **Режим:** один переключатель «Достижения и штрафы» (ДС-14). Штрафы при выключенных достижениях недоступны.
2. **Разовое событие** — один раз за учебный год.
3. **Спевка** — отдельное от урока событие, учитывается всегда, в том числе на обзорном уроке (ДС-15).
4. **Потолок ручной выдачи:** не больше баллов уровня из каталога (совпадает с 12.2 п. 8 основной спецификации).
5. **Отзыв окончателен** (ДС-7): после отзыва за те же уроки достижение больше не выдаётся, даже вручную. Чтобы «перевыдать», admin делает ручную выдачу с другими уроками.
