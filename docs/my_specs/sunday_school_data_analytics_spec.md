Не описывает: конкретные таблицы, типы колонок, индексы, ORM-модели, выбор облачных сервисов и конкретной AI-модели.

## 2. Роли и права доступа

### 2.1 Принципы

- Пользователь (взрослый с учётной записью) может иметь **несколько ролей** одновременно (например, teacher и parent).
- Права определяются парой **«роль + принадлежность ресурса»**: teacher видит и правит только свои группы, parent видит только своих детей. Одной роли недостаточно.
- **У детей нет учётных записей.** Ребёнок не входит в систему сам: родитель входит под своей учётной записью и выбирает ребёнка из списка своих детей (переключение профиля внутри сессии родителя). Система не собирает ничего напрямую от ребёнка.
- **Вход — через Google или Telegram** (решение владельца). Логинов и паролей в системе нет: подлинность подтверждает провайдер входа.
- **Первый вход — регистрация** (решение владельца): согласие на обработку персональных данных + ФИО → заявка на доступ. Пока admin не одобрил заявку и не назначил роли, пользователь не видит ничего, кроме своей регистрации и профиля (2.4).
- **Право на удаление** (решение владельца): любой пользователь может запросить удаление своей учётной записи, опекун — данных своего ребёнка (2.5).

Пользователь без одобренной заявки (статусы «Регистрация», «Заявка на рассмотрении», «Отклонена») не имеет ни одного права из матрицы. Ему доступны только регистрация, собственный профиль и запрос на удаление своей учётной записи (2.4, 2.5).

### 2.3 Семья (решение владельца)

Семья связывает родителей и детей. Отдельной сущности «Опекун» нет: взрослые — члены семьи (3.9). Ниже «опекун» означает взрослого члена семьи ребёнка с типом связи мать, отец или опекун.

**СМ-1 Ребёнок — в одной семье.** Ребёнок состоит не более чем в одной семье. Семья — это круг взрослых, отвечающих за этих детей, а не обязательно одно домохозяйство: разведённые родители остаются взрослыми одной семьи ребёнка.

**СМ-2 Взрослый — в нескольких семьях.** Взрослый с учётной записью может состоять в нескольких семьях (например, дети от первого и второго брака). Доступ parent — к детям всех семей, где он взрослый член. Так отчим из второй семьи не видит детей первой.

**СМ-3 Типы и ограничения.** У взрослого в семье тип связи: мать, отец или опекун. В семье не более одной «матери» и одного «отца»; «опекунов» — сколько угодно. Модель не ломается на неполных семьях и опеке.

**СМ-4 Взрослый без учётной записи.** Взрослого можно внести в семью без учётной записи: ФИО, тип, телефон, email. Это контакт для учителя и подписант бумажного согласия (СО-3). Когда человек зарегистрируется, admin связывает его учётную запись с этой записью (2.4).

**СМ-5 Создание семьи.** Семья создаётся в момент установления связи родителя и ребёнка:
- **при одобрении заявки с ролью parent** (2.4): если ребёнок ещё ни в какой семье — создаётся новая семья с этим пользователем и выбранными детьми; название по умолчанию — фамилия пользователя («Смирновы»);
- **вручную на странице семьи** (admin): например, чтобы собрать бумажные согласия до регистрации родителей — семья со взрослыми без учётных записей.
Пустая семья (без детей и взрослых) не сохраняется.

**СМ-6 Страница семьи** (admin): название, адрес, примечание — общие для детей семьи; взрослые (тип, контакты, учётная запись и её статус, какие согласия дал); дети (группа, статус согласия на данные и кем дано); действия — изменить данные, добавить или исключить взрослого и ребёнка, отметить бумажное согласие, перейти в профиль пользователя и карточку ученика; последние записи журнала по семье. Parent видит свою семью на странице «Данные и согласия» (только чтение) и правит свои контакты (БП-9).

**СМ-7 Исключение из семьи.** Исключённый ребёнок перестаёт быть виден взрослым семьи; если у него не остаётся семьи, admin получает предупреждение: без взрослых нельзя получить согласие (2.6). Исключение последнего взрослого — предупреждение «семья без взрослых».

**СМ-8 Учитель видит** ФИО, тип связи и телефоны взрослых семей своих учеников — чтобы связаться. Адрес и примечание — только admin.

**СМ-9 Удаление.** Удаление учётной записи взрослого (2.5) стирает его данные в записи семьи (запись остаётся как «взрослый (данные удалены)» с типом связи). Удаление данных ребёнка исключает его из семьи; если в семье не осталось детей, admin решает, удалить ли семью.

**СМ-10 Объединение и перенос.** Дубликаты семей admin объединяет; ребёнка переносит из семьи в семью. Всё — с записью в журнал.

### 2.4 Регистрация, заявка на доступ и назначение ролей (решение владельца)

Роль subscriber из v2.3–v2.7 **упразднена**. Вместо неё — статус учётной записи; роли (admin / teacher / parent) есть только у активной учётной записи.

| Статус учётной записи | Что видит пользователь | Как попадает в статус |
|---|---|---|
| **Регистрация** | только страницу регистрации и «Выйти» | первый вход через Google или Telegram |
| **Заявка на рассмотрении** | экран ожидания, свой профиль, запрос на удаление | отправил форму регистрации |
| **Отклонена** | экран с причиной отказа, свой профиль, повторная отправка, запрос на удаление | admin отклонил заявку |
| **Активна** | разделы по ролям | admin одобрил заявку и назначил роли |
| **Отключена** | вход заблокирован, данные сохраняются | admin отключил доступ |
| **Удалена** | вход невозможен; данные удалены или обезличены (2.5) | выполнен запрос на удаление |

**РГ-1 Перенаправление.** После первого входа пользователь попадает на страницу регистрации. Пока регистрация не отправлена, любой адрес приложения ведёт туда же.

**РГ-2 Согласие на обработку и хранение персональных данных.** Отдельный флажок, по умолчанию **не отмечен**; без него кнопка отправки неактивна. Рядом — краткий текст и ссылка на полный: какие данные собираются (ФИО, email или идентификатор Telegram, роли, связи с детьми, действия в системе), зачем, кто оператор (церковь), где хранятся (облачная база данных, регион), сколько хранятся, как запросить удаление (2.5). Сохраняются версия текста, дата и время согласия (3.17). Это согласие **отдельно** от согласия родителя на запись голоса ребёнка (ВП-15).

**РГ-3 Профиль.** Фамилия и имя — обязательно, отчество — необязательно. Поля предзаполняются из провайдера (Google передаёт имя и фамилию, Telegram — имя) и редактируются. Допустимы буквы, пробел, дефис, апостроф; 1–50 символов.

**РГ-4 Заявка.** Отправка формы создаёт заявку на доступ (3.20) и переводит учётную запись в статус «Заявка на рассмотрении». Admin видит число новых заявок в меню. До решения пользователь может исправить ФИО в профиле.

**РГ-5 Новая версия текста согласия.** Если текст согласия существенно изменился, активный пользователь при следующем входе снова видит согласие и не может продолжить без него. Несущественные правки (опечатки) версию не меняют.

**РГ-6 Незавершённая регистрация.** Учётная запись в статусе «Регистрация» (согласие не дано) удаляется автоматически через 30 дней: согласия нет — хранить данные нельзя. *Подтвердить — 12.2 п. 14.*

**Страница «Заявки на доступ»** (только admin):
- список заявок, сначала самые старые; у каждой: ФИО, способ входа, email (если есть), дата отправки, дата и версия согласия, сколько дней ждёт;
- **подсказка сопоставления:** если email из Google или ФИО из регистрации совпали со взрослым без учётной записи в какой-либо семье, admin видит «похоже, это Игорь Смирнов — отец в семье Смирновых (Миша, Даша)». Привязка всё равно подтверждается вручную;
- **подсказка дубликата:** похоже на второй вход уже зарегистрированного человека — «Объединить» (12.2 п. 13);
- **Одобрить:** одна или несколько ролей обязательны; для teacher — группы на текущий учебный год (3.5). Для **parent** — обязательная связь с детьми через семью, одним из трёх способов:
  - **связать с существующим взрослым** семьи (взрослый без учётной записи — по подсказке или выбором из списка);
  - **добавить в семью ребёнка:** найти ребёнка, указать тип связи — пользователь становится взрослым его семьи;
  - **создать новую семью:** выбрать детей без семьи, указать тип связи и название семьи (СМ-5).
  Если выбранный ребёнок уже в семье, вариант «создать» недоступен — только «добавить в семью ребёнка» (СМ-1). Проверяется СМ-3. После одобрения взрослый при входе видит экран согласия по каждому ребёнку семьи (СО-2). Учётная запись становится активной;
- **Отклонить:** причина обязательна и видна пользователю. Пользователь может исправить профиль и отправить заявку снова (12.2 п. 27).

**Страница «Пользователи»** (только admin): все учётные записи с фильтром по статусу и поиском. Строка ведёт в **профиль пользователя**.

**Профиль пользователя для admin:** ФИО (admin может исправить — с записью в журнал), способы входа, email, статус, даты первого и последнего входа, согласие (версия, дата), роли, группы и семьи со ссылками на страницы семей (правка ролей — здесь же), заявки и запросы на удаление с их статусами, последние записи журнала по этому пользователю. Действия: отключить и вернуть доступ, объединить с дубликатом, перейти к запросу на удаление.

**Защиты:** нельзя снять роль admin с последнего admin; admin не может снять admin с самого себя; каждое решение по заявке, изменение ролей, привязки и доступа — запись в журнале (БП-8).

**Два способа входа у одного человека.** В профиле можно привязать второй способ входа (Google ↔ Telegram). Если появились два пользователя, admin объединяет их (12.2 п. 13).

### 2.5 Удаление персональных данных (решение владельца)

**УД-1 Кто и что может запросить.**
- **Удаление своей учётной записи** — любой пользователь в любом статусе, кроме «Удалена».
- **Удаление данных ребёнка** — пользователь с ролью parent, который является взрослым членом семьи этого ребёнка (2.3). Другие взрослые семьи получают уведомление о запросе (12.2 п. 24).

**УД-2 Создание запроса.** Учётная запись — со страницы профиля; данные ребёнка — со страницы «Данные и согласия». Перед отправкой пользователь видит, что будет **удалено**, а что **обезличено** (УД-7), и что действие необратимо после выполнения. Причина необязательна. На один субъект (учётная запись или ребёнок) — не более одного открытого запроса.

**УД-3 Отмена.** Автор отменяет запрос, пока тот не выполнен (статусы «Новый», «В работе»). Отмена — запись в журнале. Выполненный запрос отменить нельзя.

**УД-4 Пока запрос открыт.** Учётная запись и данные ребёнка работают как обычно: пользователь может передумать. Исключение — голосовые записи ребёнка: с момента запроса новые записи не принимаются (удалять их всё равно придётся).

**УД-5 Срок.** Admin выполняет или отклоняет запрос не позднее чем через **15 календарных дней** (*срок проверить по применимому закону о защите персональных данных — 12.2 п. 26*). На странице запросов видно, сколько дней осталось; просроченные выделены.

**УД-6 Отклонение.** Только с причиной, которую видит автор: например, не удалось убедиться, что запрос сделал сам человек; ребёнок не связан с автором. Удаление по закону не отклоняется по усмотрению admin.

**УД-7 Правило «удалить или обезличить».** Для **учётной записи взрослого**: данные, на которые ничто не ссылается, **удаляются**; записи, где он автор (уроки, проверки, выдачи кирпичиков, журнал изменений), **обезличиваются** — личные поля стираются, запись получает имя «Удалённый пользователь №N», связи сохраняются, история школы не меняется. Для **данных ребёнка** — **полное удаление**, включая оценки (таблица ниже).

Учётная запись:

| Данные | Действие |
|---|---|
| Способы входа (идентификаторы Google и Telegram), email, сессии | удалить |
| ФИО | удалить; учётная запись → «Удалённый пользователь №N», статус «Удалена» |
| Роли, назначения преподавателя | удалить. Если преподаватель назначен на группу активного года, admin сначала видит предупреждение и назначает замену |
| Записи взрослого в семьях (3.9): ФИО, телефоны, email | это данные того же человека: стереть; запись остаётся как «взрослый (данные удалены)» с типом связи. Admin видит предупреждение, если в семье не останется взрослого с контактами (СМ-9) |
| Авторство: уроки, проверки, выдачи кирпичиков, достижения, штрафы, голосовые попытки, которые он записал | оставить, автор — «Удалённый пользователь №N» |
| Согласие на обработку ПД, решения по заявкам, сам запрос на удаление | оставить обезличенными: факт, версия, даты — подтверждение законности прошлой обработки (*проверить у юриста*) |
| Журнал изменений | оставить; ссылки ведут на обезличенную учётную запись (УД-10) |

Данные ребёнка:

**Данные ребёнка удаляются полностью (решение владельца).** Обезличенный «Ученик №N» не анонимен: в группе из 15 детей учитель по датам и оценкам узнает ребёнка. Поэтому по запросу опекуна удаляется всё, а групповые показатели пересчитываются.

| Данные | Действие |
|---|---|
| Карточка: ФИО, дата рождения, фото, медицинская информация, экстренный контакт | удалить |
| Аудио, транскрипты и оценки голосовых попыток | удалить |
| Записи проверок: присутствие, оценки за стихи, тест, тетрадь, спевка, комментарии учителя | удалить |
| Выданные достижения с доказательствами, штрафы | удалить |
| Журнал кирпичиков ребёнка | удалить — исключение из «только на добавление» (БП-11) |
| Зачисления, членство в семье, согласия (данные, голос, фото) | удалить; если в семье не осталось детей — admin решает, удалить ли семью (СМ-9) |
| Записи журнала изменений о ребёнке | оставить без личных данных: ссылка ведёт на «ребёнок (данные удалены)», старое и новое значение стираются — исключение из БП-8 |
| Сам запрос на удаление | оставить: дата, кто запросил, кто выполнил, сводка — без ФИО ребёнка (подтверждение исполнения) |

**Последствия полного удаления ребёнка:**
- групповые средние, посещаемость и графики за прошлые уроки **пересчитываются** без этого ребёнка; на экранах аналитики периода, где были его данные, admin видит пометку «данные изменены: удаление по запросу опекуна, дата» (9.1);
- достижения других детей не меняются: правила считаются по ученику, а не по группе;
- отчёты, выгруженные раньше (например, для церковного совета), не меняются — это бумаги, а не система; в разделе «как мы считали» нового отчёта упоминается, что данные удалённых детей не учитываются (9.6).

**УД-8 Выполнение.** Перед выполнением admin видит план: сколько записей будет удалено и сколько обезличено, с предупреждениями (последний контакт ребёнка, назначенный преподаватель). Подтверждение — ввод слова «удалить». Выполнение — одной транзакцией; сводка сохраняется в запросе; запись в журнале.

**УД-9 Защиты.** Запрос последнего admin не выполняется, пока не назначен другой admin. Собственный запрос admin выполняет другой admin; если admin один — тот же admin с отдельным подтверждением.

**УД-10 Журнал изменений и обезличивание.** Журнал неизменяем (БП-8). Чтобы обезличивание не требовало правки истории, журнал хранит **ссылки** на пользователя и ученика, а имена подставляет при показе. В поля «старое / новое значение» и «причина» имена людей не записываются: вместо имени — ссылка. Если имя всё же попало в свободный текст (причина, комментарий), при выполнении запроса оно заменяется обезличенным — это единственное допустимое изменение журнала.

**УД-11 Резервные копии.** Удалённые данные остаются в резервных копиях и истории восстановления базы (у Neon — окно восстановления по времени) до истечения срока их хранения. При восстановлении базы из копии выполненные запросы применяются повторно — поэтому список выполненных запросов хранится. Срок хранения копий указывается в тексте согласия (РГ-2).

**Страница «Запросы на удаление»** (только admin): вкладки «Открытые», «Выполненные», «Отклонённые и отменённые». У каждого запроса: тип (учётная запись / данные ребёнка), чей, кто запросил, дата, остаток срока, статус, план (УД-8). Действия: «Взять в работу», «Выполнить…», «Отклонить…»; ссылки на профиль пользователя и карточку ученика.

### 2.6 Согласие опекуна на обработку данных ребёнка (решение владельца)

Согласие взрослого при регистрации (РГ-2) покрывает только его собственные данные. Данные ребёнка (ФИО, дата рождения, фото, оценки, посещаемость, записи голоса) обрабатываются на основании **согласия опекуна**.

**СО-1 Когда даётся.** Когда взрослый становится членом семьи ребёнка (2.3, СМ-5). Согласие — отдельное для каждого ребёнка, с версией текста и датой (3.17). Оно не заменяет согласия на запись голоса и фотосъёмку (ВП-15): те остаются отдельными и необязательными.

**СО-2 Электронно.** Если у опекуна есть учётная запись с ролью parent, после привязки он при следующем входе видит экран согласия по каждому новому ребёнку. Пока согласие не дано, данные этого ребёнка ему не показываются. Флажок по умолчанию не отмечен.

**СО-3 На бумаге.** Если у опекуна нет учётной записи (или он не пользуется приложением), admin отмечает бумажное согласие: опекун, дата подписания, версия текста, где хранится оригинал. Отметка — запись в журнале.

**СО-4 Без согласия ребёнка не зачисляют.** Карточку ребёнка можно создать (ФИО и опекуны — чтобы было кого попросить о согласии), но зачислить в группу — только при действующем согласии хотя бы одного связанного опекуна. Карточка без согласия видна только admin с пометкой «нет согласия»; через 30 дней без согласия admin получает напоминание удалить её.

**СО-5 Переходный период.** Для детей, перенесённых из действующего приложения (Раздел 13), согласия нет. Предложено: 60 дней на сбор — электронно или на бумаге; ученики без согласия отмечены у admin и учителя. По окончании срока admin решает по каждому: продлить сбор или удалить данные (12.2 п. 28).

**СО-6 Отзыв.** Опекун отзывает согласие на странице «Данные и согласия». Если после этого у ребёнка не остаётся ни одного действующего согласия, отзыв **создаёт запрос на полное удаление данных ребёнка** (УД-1, УД-7); перед подтверждением опекун видит, что именно будет удалено. Если согласие другого опекуна действует — данные остаются, отзывающий опекун теряет доступ к ребёнку.

**СО-7 Видимость.** Учитель видит в составе группы только факт «согласие есть / нет» (без деталей). Admin — кто, когда, электронно или на бумаге, версия текста.

## 3. Сущности и данные

### 3.1 Организация (Org)
Контекст для возможного многопользовательского сценария в будущем (см. Раздел 11). Сейчас — ровно одна запись.

### 3.2 Пользователь (User) и роли
- **Фамилия, имя, отчество** (отчество необязательно) — заполняются при регистрации (РГ-3); email — если его передал провайдер (Telegram не передаёт)
- **Способы входа:** Google (идентификатор, email) и / или Telegram (идентификатор, имя пользователя); у пользователя хотя бы один
- **Статус учётной записи:** регистрация / заявка на рассмотрении / отклонена / активна / отключена / удалена (2.4); дата первого и последнего входа
- Набор ролей (admin / teacher / parent), может быть несколько; роли есть только у активной учётной записи
- После удаления (2.5): обезличенное имя «Удалённый пользователь №N», личные поля пусты
- Языка интерфейса у пользователя нет: язык общий для приложения и задаётся admin (ЛК-7)
- Пользователь с ролью parent — взрослый член одной или нескольких семей (3.9, СМ-2)

### 3.3 Группа (Grade) — постоянная
- Название (например, «Младшая группа»), описание
- Возрастной диапазон (min / max)
- Активна / неактивна
- Принадлежит организации
- **Язык группы** (ru / en) — определяет перевод Библии для золотых стихов группы (ЯГ-1…ЯГ-4). Это не язык интерфейса: интерфейс общий и задаётся admin (ЛК-7)
- **Правило:** группа не создаётся заново каждый год. Что меняется по годам — преподаватели (3.5), состав (3.8) и настройки оценивания (3.6)

**ЯГ-1 Перевод зависит от языка группы.** Язык группы (ru / en) выбирает admin в настройках группы. Каждому языку соответствует перевод Библии по умолчанию (3.10, ПБ-3). Золотые стихи группы показываются, проверяются и озвучиваются только в этом переводе.

**ЯГ-2 Язык группы ≠ язык интерфейса.** Англоязычная группа может работать в русском интерфейсе и наоборот. Язык интерфейса — одна настройка на всё приложение (ЛК-7); язык группы — настройка группы. Названия книг в ссылках («Ин. 3:16» / «John 3:16») показываются по языку группы.

**ЯГ-3 Нельзя выбрать язык без загруженного перевода.** В списке доступны только языки, для которых перевод загружен и помечен «готов» (ПБ-5). Новая группа получает язык по умолчанию — ru.

**ЯГ-4 Смена языка группы.** Меняет admin; интерфейс предупреждает: тексты золотых стихов во всех уроках группы будут показаны в новом переводе, а проверки голоса пойдут по новому тексту. Уже сохранённые оценки не меняются, у каждой голосовой попытки остаётся перевод, по которому она проверялась (ВП-17). Смена — запись в журнале (3.16).

### 3.4 Учебный год (AcademicYear) — общешкольный
- Название, дата начала, дата окончания
- Статус: черновик / активен / завершён
- **Правила:** в школе одновременно не более одного активного учебного года; активирует и закрывает его admin (БП-6)
- При создании нового года система предлагает даты по умолчанию и **копирует** настройки оценивания и назначения преподавателей из прошлого года (admin правит)

### 3.5 Назначение преподавателя (TeacherAssignment)
- Преподаватель (пользователь с ролью teacher) + группа + учебный год
- Групп у преподавателя может быть несколько; преподавателей у группы — несколько
- Права teacher (2.2) определяются назначением **в активном году**; на данные завершённых лет teacher сохраняет доступ только для чтения по своим прошлым назначениям

### 3.6 Настройки оценивания (GradeSettings)
- Привязаны к паре **группа + учебный год** (один-к-одному)
- Переключатели: учитывать ли золотые стихи / тест / тетрадь / спевку
- **Максимальное количество золотых стихов на урок** — настраиваемое число, не константа
- Кастомные названия параметров (например, «Memory Verse» вместо «Золотые стихи»)
- Баллы / веса для каждого параметра (формула — Раздел 12, п. 6)
- **Дней для зачёта стиха (N)** — сколько разных дней ребёнок должен рассказать стих с хорошим результатом, чтобы получить 2 балла (ВП-8, ВП-16). По умолчанию 3
- **Режим «Достижения и штрафы»** — включён / выключен, с историей периодов выключения. Переключает teacher своей группы или admin; полученные достижения при выключении сохраняются (ДС-14 в `achievements_spec.md`)
- Язык группы и перевод Библии — свойство группы (3.3, ЯГ-1), а не года; в интерфейсе стоит рядом с настройками оценивания
- Параметры голосовой проверки группы (Раздел 6, ВП-9) — пороги качества и число дней для 1 балла; значения определяются после теста

### 3.7 Ученик (Pupil)
- ФИО (фамилия, имя; отчество опционально), дата рождения, фото (необязательно)
- Активен / неактивен
- Собственной учётной записи нет
- Ученик может **не состоять ни в одной группе** (список «неназначенные»)
- Кто создаёт карточки учеников — см. Раздел 12, п. 1
- Статус согласия опекуна на обработку данных (2.6): есть / нет
- После удаления данных по запросу опекуна (2.5) ученик и все связанные с ним записи удаляются полностью (УД-7)

### 3.8 Зачисление в группу (Enrollment)
- Ученик + группа + учебный год + дата начала + дата окончания (пусто, пока ученик в группе)
- В любой момент времени у ученика **не более одного активного зачисления**
- Пакетное добавление и удаление учеников в группу — это массовое создание и закрытие зачислений
- Удаление из группы **не удаляет** историю проверок (БП-7); ученик становится «неназначенным»
- Перевод между группами — закрытие одного зачисления и создание другого
- Зачисление возможно только при действующем согласии опекуна на обработку данных ребёнка (СО-4)

### 3.9 Семья (Family) и взрослые члены семьи (FamilyAdult)
- **Семья:** название (обычно фамилия — «Смирновы»), адрес, примечание, дата создания; кто создал (при одобрении заявки или вручную)
- **Взрослый член семьи:** семья, ФИО, тип связи (мать / отец / опекун), телефон(ы), email; необязательная ссылка на учётную запись пользователя (СМ-4)
- **Дети семьи:** ученики (3.7); у ученика не более одной семьи (СМ-1)
- Правила — 2.3 (СМ-1…СМ-10)

### 3.10 Переводы Библии, стих Библии (BibleVerse) и золотой стих (GoldenVerse)
- **Перевод (BibleTranslation):** код (например, `ru-synodal`), язык (ru / en), название, источник и условия лицензии, статус (нет данных / загружается / готов), перевод по умолчанию для языка
- **Книга (BibleBook):** общий для всех переводов справочник: порядковый номер, названия и сокращения на ru и en («Ин.» / «John»)
- **Стих Библии (BibleVerse):** перевод + книга + глава + стих + текст. Один и тот же стих существует в каждом переводе отдельной строкой
- **Золотой стих:** справочник, общий для организации, не дублируется по группам и переводам. Это **диапазон** стихов Библии (от стиха до стиха; одиночный стих — частный случай) в **общей нумерации** (ПБ-4); ссылка отображается как «Ин. 3:16» или «Пс. 22:1–3» / «John 3:16»
- **Правило:** текст золотого стиха не копируется — он собирается из стихов диапазона **в переводе группы**; урок ссылается на золотой стих, а не на текст
- Эталонный текст может содержать редакторскую разметку (например, `^^Псалом Давида.^^`, `[к народу]`). Для сравнения при голосовой проверке она **исключается** (ВП-5), но в справочнике и при показе остаётся
- Если золотой стих изменили, то уже проведённые уроки показывают актуальный текст; изменение ссылки у использованного стиха запрещено (создаётся новый)

**ПБ-1 Данные приходят скриптами владельца.** Тексты русского и английского переводов загружают скрипты, которые владелец предоставит в процессе разработки. Приложение их не пишет и не переводит само; пока скрипты не получены, схема и справочник книг готовы, а таблица стихов пуста. *Скрипты и данные предоставлены: см. [`Bible/README.md`](./Bible/README.md) (состав, формат, порядок загрузки, расхождения со схемой).*

**ПБ-2 Скрипты загрузки.** Идемпотентны (повторный запуск не создаёт дублей и не портит данные), работают в обоих окружениях (Раздел 15), в конце сверяют число загруженных стихов с ожидаемым и сообщают расхождения. Запуск скрипта — запись в журнале. Править тексты Библии через интерфейс нельзя.

**ПБ-3 Перевод группы.** Перевод группы = перевод по умолчанию для её языка (ЯГ-1). Выбор конкретного перевода внутри языка (если их когда-то будет несколько) — вне первой версии: пока один перевод на язык.

**ПБ-4 Общая нумерация.** Русская (Синодальная) и английская нумерации различаются: например, Синодальный Пс. 22 — это Ps. 23 в английских изданиях, а у многих псалмов по-разному считаются заголовки и стихи. Золотой стих хранится в одной **общей нумерации**, а скрипты загрузки приводят каждый перевод к ней. Какую нумерацию взять общей и как проверять сопоставление — открытый вопрос 12.2 п. 29; без решения английский текст стиха из псалмов может оказаться чужим.

**ПБ-5 Готовность перевода.** Язык можно назначить группе, только когда перевод «готов» (ЯГ-3). Если золотой стих нельзя собрать в переводе группы (в тексте нет какого-то стиха), урок с ним сохранить нельзя — форма показывает, каких стихов не хватает.

**ПБ-6 Условия использования текста.** Синодальный перевод находится в общественном достоянии. Лицензия английского перевода зависит от выбора владельца (многие современные переводы лицензированы и ограничивают объём цитирования или коммерческое использование); название и условия хранятся в карточке перевода, проверка — до загрузки (12.2 п. 30).

**ПБ-7 Размещение справочника.** Справочник общий для всех групп организации; отдельной копии на группу нет. Объём (несколько десятков тысяч строк на перевод) мал для базы, но тексты читаются на каждом экране урока и проверки — поэтому доступ идёт по индексу (перевод, книга, глава, стих) и кэшируется (физическая схема — следующий шаг).

### 3.11 Урок (Lesson)
- Привязан к группе (учебный год определяется датой и активным годом группы); может быть создан только в активном учебном году, дата — в границах года
- Название (тема), дата, порядковый номер в году, **ведущий преподаватель** — учитель, который проводит урок (УЧ-1…УЧ-4)
- **Тип урока** (выбирается при создании): **обычный** или **обзорный**. На обзорном уроке золотые стихи не задаются и не рассказываются, тест не пишется; оцениваются тетрадь и спевка, присутствие отмечается как обычно. Обзорный урок — пропуск для серий по стихам и тестам (ДС-15 в `achievements_spec.md`). Сменить тип можно, пока по уроку нет проверок
- Содержание урока — форматированный текст (редактор)
- Связан с 0..N золотыми стихами с порядком (1-й, 2-й, 3-й стих); у обзорного урока — 0
- Может быть связан с событием календаря типа «урок» (3.18)
- **Статус:** проведён → **«проверка завершена»** (отметка учителя, что посещаемость и ДЗ по уроку внесены). Эта отметка — событие, запускающее пересчёт достижений (ДС-6). **Отмена урока — это событие календаря (3.18), урока в этом случае нет**
- **Правило:** количество стихов на урок ограничено значением из настроек группы, но это бизнес-правило, а не жёсткая структура
- **УЧ-1 Кто ведёт — обязательное поле формы урока.** Выбор из учителей, назначенных на эту группу в учебном году урока (3.5). Учителя другой группы или пользователя без назначения выбрать нельзя.
- **УЧ-2 По умолчанию — текущий пользователь**, если он назначен на группу. Если не назначен (например, admin, не прикреплённый к группе), поле пустое и форма требует выбрать учителя. Учитель может создать урок «за коллегу», выбрав его в списке.
- **УЧ-3 Ведущий и проверяющий — разные вещи.** Проверять ДЗ и править оценки может любой учитель группы (2.2); «ведёт» нужно для истории и аналитики (9.1.4). Ведущий не получает дополнительных прав.
- **УЧ-4 Изменение.** Ведущего можно сменить в любой момент при редактировании урока (замена заболевшего и т. п.); смена — запись в журнале (3.16). Если назначение учителя на группу позже снято или его учётная запись удалена (2.5), урок сохраняет ссылку (после удаления — «Удалённый пользователь №N»). Замена учителем не из группы — открытый вопрос (12.2 п. 31).
- Удаление урока: допускается только для уроков без проверок; иначе только admin и с записью в журнал

### 3.12 Отметка ДЗ / посещаемости (HomeworkCheck)
Одна запись = один ученик на одном уроке.
- Присутствовал (да / нет). **Не влияет на баллы и на «подходящий урок»** (БП-10, ДС-2). По умолчанию — нет, пока учитель явно не отметит
- ДЗ проверено (да / нет)
- Оценки за золотые стихи, **заданные на предыдущем уроке** (их рассказывают на этом, БП-2) — набор записей «стих → оценка 0–2» (0..N), каждая со ссылкой на стих и урок, где его задали. **Для каждой оценки хранится источник:** вручную / голосовая проверка. Ручная оценка приоритетнее (ВП-12)
- Балл за тест 0–10 (или «не оценивалось»)
- Балл за тетрадь 0–10 (или «не оценивалось» — отдельно от «оценено как 0», БП-4)
- Спевка (да / нет)
- **Комментарий учителя** (необязательно)
- Итоговые баллы за запись (вычисляемое значение; формула и хранение — БП-5, Раздел 12, п. 6)
- **У каждой оценки** (стих, тест, тетрадь, спевка) хранятся **дата выставления** и **кто выставил**. Если оценка выставлена после даты следующего урока группы, запись получает отметку **«сдано позже»** (вычисляется, не вводится вручную)
- На обзорном уроке запись содержит присутствие, балл за тетрадь, спевку и комментарий
- Проверку можно сохранять частично и продолжить позже; правка уже проверенной записи — по БП-12

### 3.14 Достижение — каталог (Achievement) — `achievements_spec.md`, раздел 2
Одна запись каталога — либо **достижение** (pointsValue ≥ 0), либо **штраф** (pointsValue < 0, ШТ-1). Вид задаётся полем и не меняется после первой выдачи.
### 3.15 Выданное достижение, доказательства, штраф — `achievements_spec.md`, разделы 4, 6, 7
Каждая выдача хранит доказательства — записи проверки (3.12), на которых она основана; пара «достижение + уровень + запись» уникальна (ДС-3, ДС-12).
У выданного штрафа дополнительно: урок, на котором было нарушение; статус (действует / снят); кто, когда и почему снял (ШТ-7).

### 3.16 Журнал изменений (AuditLog)
- Кто (ссылка на пользователя), когда, над какой сущностью (ссылка), какое действие, старое и новое значение, причина (опционально), источник (пользователь / система). Имена людей хранятся ссылками, а не текстом (УД-10)
- Обязательно фиксируются: назначение и снятие ролей, отключение доступа, объединение пользователей, правки отметок ДЗ и посещаемости, ручная выдача и отзыв достижений (включая изменённые баллы), выдача, изменение и снятие штрафов, ручная правка авто-оценки стиха, назначение ролей, создание и изменение опекунов и связей, смена ведущего учителя урока, смена языка группы, запуск скриптов загрузки Библии, активация и закрытие учебного года, зачисления и исключения, изменение настроек группы и каталога достижений, корректирующие записи журнала кирпичиков, решения по заявкам на доступ, создание, отмена, отклонение и выполнение запросов на удаление, правка ФИО пользователя admin

### 3.17 Согласие (Consent)
- **Согласие пользователя на обработку и хранение своих персональных данных** (РГ-2): кто, версия текста, дата и время; обязательно для отправки заявки. Отзыв этого согласия = запрос на удаление учётной записи (2.5)
- **Согласие опекуна на обработку данных ребёнка** (2.6): опекун, ребёнок, способ (электронно / на бумаге — кто отметил и где хранится оригинал), версия текста, дата, статус (действует / отозвано). Обязательно для зачисления (СО-4)
- **Согласия родителя за ребёнка на голос и фото:** кто дал (родитель), за какого ребёнка, тип согласия (запись голоса и её обработка внешним AI-сервисом; фотосъёмка), дата и время, **версия текста согласия**, статус (действует / отозвано)
- Без действующего согласия на запись голоса голосовая проверка для этого ребёнка недоступна

### 3.18 Событие календаря (GradeEvent)
- Группа + дата + тип + название + описание
- Типы: **урок**, **выездное мероприятие**, **отмена урока**
- Событие «урок» может быть связано с уроком (3.11); открытие события ведёт на урок
- Права — матрица 2.2; parent видит календарь группы своего ребёнка, не редактируя

### 3.19 Журнал выдачи кирпичиков (BrickLedger)
- Запись: ученик + учебный год + количество (целое, может быть отрицательным только для корректировки) + дата выдачи + кто выдал + примечание
- Назначение: физический кирпичик (бумажный) выдаётся ребёнку за набранные баллы; журнал фиксирует **фактически выданное**
- Правила — БП-11

### 3.20 Заявка на доступ (AccessRequest)
- Пользователь, дата отправки, ФИО на момент отправки, ссылка на согласие (3.17)
- Статус: на рассмотрении / одобрена / отклонена; кто и когда решил; причина отказа; назначенные роли
- Повторная отправка после отказа — новая заявка; история заявок видна в профиле пользователя у admin

### 3.21 Запрос на удаление (DeletionRequest)
- Тип: учётная запись / данные ребёнка; субъект (пользователь или ученик); кто запросил; дата; причина (необязательно)
- Статус: новый / в работе / выполнен / отклонён / отменён; срок (УД-5); кто взял в работу, кто выполнил или отклонил, когда; причина отказа или отмены
- Сводка выполнения: сколько записей удалено и обезличено по видам (УД-8)
- После выполнения запрос остаётся в обезличенном виде (УД-7, УД-11)

## 4. Связи и мощность

- Организация 1 → N групп, N учебных годов, N пользователей, N золотых стихов, N достижений (каталог)
- Группа × учебный год 1 → 1 настройки оценивания
- Группа × учебный год N ↔ N преподавателей (назначения)

- Семья 1 → N детей; ученик 0..1 → семья (СМ-1)
- Семья 1 → N взрослых членов (не более одной «матери» и одного «отца», СМ-3); взрослый член 0..1 → пользователь; пользователь 0..N → взрослые члены в разных семьях (СМ-2)
- Группа N → 1 язык (ru / en) → 1 перевод Библии по умолчанию
- Перевод Библии 1 → N стихов; книга 1 → N стихов (по одному на перевод)
- Урок N → 1 ведущий преподаватель (назначенный на группу в год урока); преподаватель 1 → N уроков
- Группа 1 → N событий календаря; событие «урок» 0..1 → урок
- Золотой стих 1 → диапазон стихов Библии
- Урок N → N золотых стихов (с порядком)
- Урок 1 → N отметок ДЗ; ученик 1 → N отметок ДЗ
- Золотой стих урока × ребёнок 1 → N попыток рассказывания
- Ребёнок 1 → N выданных достижений; выдача 1 → N доказательств (записей проверки); запись проверки × достижение × уровень — не более одной выдачи (ДС-3, ДС-12). Серии повторяемы (ДС-11); накопление и разовое событие — не более одной выдачи уровня за учебный год
- Ребёнок 1 → N штрафов; урок × ребёнок — не более одного действующего штрафа (ШТ-4)
- Ребёнок × учебный год 1 → N записей журнала кирпичиков
- Пользователь 1 → N заявок на доступ (не более одной на рассмотрении); пользователь 1 → N согласий на обработку ПД (по версиям текста)
- Пользователь или ученик 1 → N запросов на удаление (не более одного открытого)

## 5. Бизнес-правила

*Обязательны для реализации. БП-1…БП-4 проверены на практике (взяты из работающего отчёта прототипа).*

### БП-1 Основная выборка для групповых средних *(было 4.1)*
В расчёт групповых средних (посещаемость, средний балл) попадают только ученики со статусом «активен» и посещаемостью ≥50% от проверенных уроков текущего учебного года, **считая от даты начала зачисления в эту группу**. Остальные активные ученики исключаются из средних, но показываются отдельным списком с числом занятий и % посещаемости.
- **Проверенный урок** — урок, у которого есть хотя бы одна запись с отметкой «ДЗ проверено».
- **Знаменатель явки** — проверенные уроки с даты отсчёта, на которых у ученика есть запись. Если записи нет вовсе, это **дефект журнала**: урок не идёт в знаменатель, а дефект попадает в счётчик качества данных (9.1).
- **Дата отсчёта** — дата зачисления. Для перенесённых из старого приложения данных — более ранняя из двух: дата зачисления или дата самого раннего проверенного урока, где у ученика есть запись (в старых данных «дата создания» ученика — техническая дата миграции).
- Слои: A — основная выборка; B — активен, явка ниже 50%; C — неактивен; D — активен, но нет ни одного проверенного урока после даты отсчёта.

### БП-2 Зачёт золотого стиха *(было 4.2)*
Стихи, **заданные на уроке N, рассказывают на следующем обычном уроке** (обозначим его N+1). Обзорный урок (3.11) пропускается: если за уроком N идёт обзорный, стихи урока N рассказывают на первом обычном уроке после него. Поэтому:
- экран проверки урока N+1 показывает стихи урока N, а каждая оценка хранится со ссылкой на конкретный стих и урок, где его задали (3.12);
- в аналитике наблюдение относится к уроку, **где рассказывали** (N+1). Первый обычный урок года не участвует: перед ним ничего не задавали; обзорный урок не участвует никогда;
- наблюдение засчитывается, если запись урока N+1 проверена и ученик **присутствовал**; учитываются только стихи с выставленной оценкой; «рассказан» — оценка 1 или 2;
- оценки голосовой проверки (ВП-8) относятся к тому же уроку N+1: окно практики закрывается на нём.

### БП-3 Зачёт теста *(было 4.3)*
В отчётное среднее теста идёт оценка с **проверенной** записи урока, где ученик **присутствовал**, **а также** оценка с отметкой «сдано позже» (БП-12, решение владельца). Отсутствие оценки («не оценивалось») в среднее не входит. *Правило v2.0 «засчитывается, если был на следующем уроке» снято: обновлённая методика отчёта его не использует.*

### БП-4 Нулевая оценка за тетрадь *(было 4.4)*
Тетрадь считается так же, как тест (БП-3): проверенная запись + присутствие, либо «сдано позже». «Не оценивалось» в среднее не входит, а «оценено как 0» входит: это разные значения на уровне данных. В перенесённых данных, где такого различия нет, 0 считается оценкой — так же, как в отчёте v1.0 (*подтвердить — Раздел 12, п. 16*).

### БП-5 Формула баллов и пересчёт при смене настроек *(было 4.5)* — **решено 2026-10-10: вариант А**
В действующем приложении настройки хранят баллы за параметры (`pointsTest` и другие), а формула суммирует «сырые» оценки (`тест + тетрадь + стихи`) и баллы за спевку: настройки и формула расходятся. Нужно решить: (а) как веса участвуют в итоговом балле; (б) при смене весов в середине года пересчитывать историю или оставлять баллы «замороженными» на момент выставления (Раздел 12, п. 6). Упрощено тем, что настройки принадлежат паре группа + год.

### БП-6 Учебный год
- Активирует и закрывает учебный год только admin
- В школе не более одного активного года одновременно
- Уроки создаются только в активном году
- При закрытии: данные года становятся **только для чтения** для teacher и parent; admin может править с записью в журнал; открытые окна голосовых попыток закрываются; выполняется финальный пересчёт достижений года; назначения и зачисления получают дату окончания (группа остаётся активной)
- Выдача кирпичиков за завершённый год остаётся доступна (награды выдаются с задержкой); см. Раздел 12, п. 10

### БП-7 Перевод ученика между группами
- История зачислений сохраняется; отметки ДЗ остаются привязаны к урокам (а значит, к группам), где они были выставлены
- Групповая аналитика группы учитывает только отметки за период зачисления ученика в эту группу (БП-1 «после зачисления» применяется к дате зачисления в **эту** группу)
- Личная аналитика ученика (для родителя и admin) охватывает все группы в рамках учебного года
- Достижения и кирпичики считаются по ученику, а не по группе: уроки разных групп упорядочиваются по дате

### БП-8 Журнал изменений
Каждое изменение из перечня 3.16 фиксируется автоматически, независимо от роли изменяющего (включая admin). Запись журнала не редактируется и не удаляется. Исключения — обезличивание имён по выполненному запросу на удаление учётной записи (УД-10) и стирание значений в записях о ребёнке при полном удалении его данных (УД-7).

### БП-9 Что parent может редактировать
Предложено: **свои контакты в записи взрослого семьи, медицинскую информацию (аллергии, ограничения), экстренный контакт, согласия** своих детей. Оценки, посещаемость, баллы, достижения и кирпичики для родителя — только чтение: иначе падает доверие к данным. *Требует подтверждения — Раздел 12, п. 2.*

### БП-10 Баллы и присутствие (решение владельца)
Баллы за урок начисляются по результатам (стихи, тест, тетрадь, спевка) и **не зависят от присутствия на уроке**: ученик мог отсутствовать, но позже сдать задания. Присутствие используется для статистики посещаемости (БП-1) и больше нигде. БП-3 (зачёт теста) применяется только к отчётному среднему балла за тест и не влияет на баллы, кирпичики и достижения (*подтвердить — Раздел 12, п. 7*).

### БП-11 Кирпичики
- **1 балл = 1 кирпичик.** Кирпичик — физическая награда; в системе учитывается её баланс
- **Набрано** (ученик × учебный год) = сумма баллов проверенных ДЗ за год (HomeworkCheck с «ДЗ проверено») + сумма баллов за достижения, полученные в этом году (ДС-10) − сумма действующих штрафов этого года (ШТ-5)
- **Выдано** = сумма записей журнала (3.19) за год. **Остаток** = набрано − выдано
- Контекст расчёта — ученик + год. В отличие от действующего приложения, группа не участвует: перевод между группами не теряет кирпичики (*подтвердить — Раздел 12, п. 10*)
- В момент выдачи нельзя выдать больше остатка; количество — положительное целое
- Журнал **только на добавление**. Единственное исключение — полное удаление данных ребёнка по запросу опекуна (УД-7): его записи удаляются целиком. Ошибку исправляет компенсирующая запись (отрицательное количество) с обязательным примечанием; записи не редактируются и не удаляются (БП-8)
- Если после выдачи баллы уменьшились (правка проверки, отзыв достижения, штраф), остаток может стать отрицательным. Это не «долг ребёнка»: родитель видит выданное и набранное, а отрицательный остаток видят только teacher и admin с пометкой «требует внимания»

### БП-12 Корректировка уже проверенных уроков (решение владельца)
Типовой случай: ребёнок отсутствовал на уроке, а позже принёс тетрадь с выполненным заданием или рассказал стих.
- **Кто и когда.** Teacher своей группы — в течение **активного** учебного года, без ограничения по давности. После закрытия года — только admin и с обязательной причиной (БП-6).
- **Что можно менять.** Любую оценку записи, присутствие, комментарий. Если записи об ученике на уроке не было (ученик добавлен позже), её можно создать.
- **Присутствие не меняется задним числом** из-за поздней сдачи: «не был на уроке» остаётся «не был». Баллы при этом начисляются полностью (БП-10).
- **К какой дате относится оценка.** К дате урока, а не к дате сдачи (как в БП-2): график «средний балл тетради» за 27.09 учитывает тетрадь, принесённую 11.10. Дата фактической сдачи хранится отдельно (3.12) и видна в карточке ученика как «сдано позже».
- **Тест, сданный позже,** засчитывается в отчётное среднее теста (решение владельца, БП-3).
- **Последствия правки:** баллы урока пересчитываются; «набрано» кирпичиков меняется сразу (БП-11); для ученика запускается пересчёт достижений (ДС-6); уменьшение оценки достижения не отзывает (ДС-7); оценка из голосовой проверки заменяется ручной (ВП-12).
- **Журнал.** Каждая правка проверенного урока — запись в журнале изменений со старым и новым значением (БП-8). Причина для teacher в активном году необязательна, но интерфейс предлагает быстрые варианты («сдал позже», «ошибка ввода»).
- **Видимость.** В таблице урока исправленная запись помечается; в карточке ученика у оценки видно «сдано 11.10». Родитель в еженедельном дайджесте видит «тетрадь за 27.09 принята».
- **Статус урока** при правке не меняется: урок остаётся «проверка завершена», повторно завершать его не нужно.

## 6. Голосовая проверка заучивания золотых стихов

### 6.1 Цель

Сократить время учителя на ручную проверку заучивания и увеличить количество стихов, которые ребёнок реально выучивает, — за счёт регулярной практики дома с понятной обратной связью. Автоматическая оценка — **предварительная**: учитель всегда может её переопределить (ВП-12).

### 6.2 Предварительное условие (gate перед разработкой)

Прежде чем проектировать хранилище и обработку, нужно проверить жизнеспособность распознавания на реальных данных:
1. Собрать **30–50 коротких записей** чтения стихов реальными детьми группы — с письменного согласия родителей.
2. Прогнать **2–3 кандидата** (управляемый облачный STT, Whisper-класс через API и т. п.).
3. Измерить: долю ошибок слов на эталонном тексте; **долю ложных отказов** (верно рассказанный стих признан неверным) — главный показатель; поведение на тишине и бормотании (не должно «выдумывать» текст); стоимость и задержку одной попытки; условия обработки данных у провайдера.
4. По результатам выбрать модель и **только после этого** зафиксировать пороги качества (решение владельца: пороги не определяются заранее).

Если на детских голосах результат неприемлем, голосовая проверка остаётся в виде «ребёнок записывает — учитель слушает», без автоматической оценки.

### 6.3 Сценарий

1. Родитель входит под своей учётной записью и выбирает ребёнка из **списка своих детей** (ВП-1).
2. По умолчанию система предлагает стихи **последнего проведённого урока** группы ребёнка; выбор другого урока возможен, но необязателен (ВП-2).
3. На экране записи показывается **только ссылка на стих** (например, «Ин. 6:68»); текст скрыт, чтобы ребёнок рассказывал по памяти, а не читал (ВП-3).
4. Родитель нажимает кнопку, ребёнок рассказывает, запись сохраняется.
5. Запись обрабатывается **асинхронно**: экран показывает «проверяем…» и затем результат (ВП-4).
6. Ребёнок получает обратную связь (ВП-10); родитель — подробности.
7. Попытки можно повторять в течение нескольких дней; балл за стих определяется по правилу окна (ВП-8).

### 6.4 Сущность «Попытка рассказать стих» (RecitationAttempt)
- Ребёнок, стих урока, пользователь-родитель, который записал
- Ссылка на аудио, дата и время, длительность, **дата удаления аудио** (ВП-14)
- Статус обработки: загружено / в обработке / оценено / ошибка (с причиной: тишина, слишком коротко, неразборчиво, технический сбой)
- Транскрипт (текст распознавания)
- Результат сравнения: процент совпадения с эталоном, пословная разметка (верно / пропущено / лишнее / не на месте)
- Идентификатор и версия использованной модели распознавания (для воспроизводимости оценок); **перевод Библии**, по эталону которого проверялась попытка (ВП-17)
- Итог попытки в шкале качества 0–100

### 6.5 Правила

**ВП-1 Профиль ребёнка вместо входа ребёнка.** Ребёнок не аутентифицируется. Все действия совершает родитель; в журнале и данных попытки фиксируется, какой родитель записал попытку и за какого ребёнка. Родитель видит в списке только детей, с которыми он связан (2.3).

**ВП-2 Выбор стиха.** По умолчанию — стихи последнего проведённого урока группы ребёнка (окно недели, ВП-8). Отдельным списком — **невыученные стихи прошедших уроков** учебного года (ВП-16): урок, сколько стихов выучено и сколько осталось.

**ВП-3 Текст скрыт во время записи.** Показывается ссылка; текст стиха открывается только после получения результата, как разбор.

**ВП-4 Асинхронная обработка и ошибки.** Пользователь не ждёт на экране без ответа: показывается статус обработки. Попытка со статусом «ошибка по техническим причинам» **не расходует** дневной лимит и **не учитывается** в окне. Попытка со статусом «тишина / слишком коротко / неразборчиво» учитывается в лимите, но не засчитывается в окне, и ребёнок получает мягкое предложение попробовать ещё раз.

**ВП-5 Детерминированная оценка.** Процент совпадения считается **программно** по пословному выравниванию записанного текста с эталоном:
- эталон берётся **в переводе группы ребёнка** (ЯГ-1) и нормализуется: убирается редакторская разметка, регистр, знаки препинания; для русского — ё/е, для английского — апострофы и дефисы;
- сравниваются слова и их порядок; учитываются пропуски, лишние слова, перестановки;
- **AI-модель не выставляет балл «на глаз».** Если используется языковая модель, то только для формулировки короткой тёплой фразы обратной связи (необязательно на первом этапе).

**ВП-6 Ограничение подсказок распознаванию.** Модели распознавания нельзя передавать полный эталонный текст стиха как подсказку: она «додумает» правильный текст за ребёнка, и оценка будет завышена. Допустимо передавать словарь редких слов (например, «алкать», «стезя»).

**ВП-7 Приоритет ошибок.** Система настраивается так, чтобы ложный отказ («выучил, а система говорит — нет») был редким. Для ребёнка он вреднее, чем редкое завышение: завышение выявляется выборочной проверкой в классе.

**ВП-8 Окно и правило «N дней».**
- Окно попыток для стиха урока: **от даты урока, где стих задан, до даты следующего обычного урока группы** (согласуется с БП-2; обзорный урок окно не закрывает).
- В каждый календарный день засчитывается **лучшая попытка дня**; несколько попыток в один день баллов не копят.
- Балл за стих определяется числом **разных дней**, в которые лучшая попытка достигла порога качества. Структура правила: 2 балла — не менее *N* дней с качеством не ниже *T_high* (*N* — настройка группы «дней для зачёта стиха», по умолчанию 3); 1 балл — не менее *N_mid* дней с качеством не ниже *T_mid*; иначе 0. Шкала 0 / 1 / 2 совпадает со шкалой прототипа и ручной проверки учителя.
- Значения *T_high, N_mid, T_mid* **не определены**: фиксируются после теста на реальных записях (6.2). Хранятся как настройки группы (3.6).
- После закрытия окна невыученный стих переходит в список прошедших уроков (ВП-16): уже набранные дни практики сохраняются.
- Пока окно открыто, родитель видит **прогресс** («2 дня из 3»). Окончательный балл фиксируется при закрытии окна.

**ВП-9 Параметры группы.** Пороги и число дней — настройки группы. Прочие параметры, определяемые после теста: максимальная длительность записи, дневной лимит попыток на один стих, использование языковой модели для фраз обратной связи.

**ВП-10 Обратная связь ребёнку.** После каждой попытки: 1–3 звезды, подсветка слов текста (выучено / пропущено — после открытия текста), одна короткая тёплая фраза. Без стыдящих формулировок; при слабом результате — предложение попробовать ещё. Голосовое озвучивание результата — отложено до последующих этапов. Проценты и пословный разбор доступны родителю, а не ребёнку.

**ВП-11 Геймификация голосовой практики.** В разумных пределах: звёзды за попытку и достижения за регулярность (Раздел 7). Награждается усилие и постоянство, а не накопление попыток в один день.

**ВП-12 Приоритет ручной оценки.** Учитель или admin могут в любой момент выставить балл за стих вручную. Ручная оценка помечается источником «вручную» и **не перезаписывается** автоматической. Каждое переопределение фиксируется в журнале (БП-8).

**ВП-13 Доступ к записям.** Аудио и транскрипт попытки доступны: родителю этого ребёнка, преподавателям группы ребёнка, admin. Больше никому.

**ВП-14 Хранение (решение владельца).**
- **Транскрипт, процент совпадения, пословная разметка и итоговый балл** хранятся постоянно (в рамках хранения данных об ученике).
- **Аудио хранится 200 дней** с момента попытки, затем удаляется автоматически. После удаления аудио оценки и транскрипты не меняются.
- Родитель может запросить **досрочное удаление** записей своего ребёнка; admin выполняет и фиксирует в журнале.
- При отзыве согласия (3.17) новые записи блокируются, существующее аудио удаляется.

**ВП-15 Согласие и приватность.**
- Запись голоса детей — чувствительные данные. Хранилище закрыто от публичного доступа, данные шифруются.
- Перед первой записью — **явное отдельное согласие родителя** (3.17); в тексте согласия указано: что записывается, что запись обрабатывает внешний AI-сервис, срок хранения аудио (200 дней), право отозвать согласие и запросить удаление.
- Провайдер распознавания выбирается с учётом условий обработки: данные не должны использоваться для обучения чужих моделей; регион обработки должен быть известен.
- Ограничение числа попыток в день защищает и от злоупотреблений, и от лишних расходов.

**ВП-16 Стихи прошедших уроков (решение владельца).**
Ребёнок может рассказать стих урока, окно которого уже закрылось, если за этот стих у него меньше 2 баллов.
- **Что доступно.** Все стихи учебного года, заданные на уроках, где ребёнок был зачислен, с текущей оценкой 0, 1 или «не оценивалось». После закрытия учебного года — недоступно.
- **Список для родителя.** Уроки с невыученными стихами: дата, тема, «выучено 1 из 3». По нажатию — стихи урока со статусом и прогрессом «2 из 3 дней». Порядок — сначала ближайшие по дате, чтобы не было завала из старых уроков.
- **Алгоритм начисления** (тот же счётчик дней, что и в ВП-8, но без окна):
  1. в каждый календарный день по каждому стиху засчитывается **лучшая попытка дня**; разные стихи можно практиковать в один день;
  2. день считается, если лучшая попытка достигла *T_high*; дни, набранные внутри недельного окна, тоже учитываются — прогресс не обнуляется;
  3. когда набрано *N* разных дней (настройка группы), оценка стиха становится **2**; при *N_mid* днях с качеством не ниже *T_mid* — **1**, если раньше было 0 или «не оценивалось»;
  4. оценка **только растёт**: начисляется разница между новой и прежней оценкой (например, было 1 — стало 2: +1 балл и +1 кирпичик). Понизить оценку практика не может;
  5. оценка записывается в запись того урока, на котором стих должны были рассказать (урок N+1, БП-2), с отметкой «сдано позже» и датой (БП-12); ручная оценка учителя по-прежнему приоритетнее (ВП-12);
  6. в групповую аналитику оценка попадает как «сдано позже» и относится к дате урока.
- **Почему полный балл, а не урезанный.** Цель — выучить стих, а не успеть к сроку. Урезание наказывало бы детей, которые пропустили урок по болезни, и противоречит принципам ДС-1 и БП-10. От откладывания «на потом» защищают три вещи: требование *N* разных дней (стих нельзя «закрыть» за один вечер), серийные достижения считаются только по оценкам на момент закрытия окна (ДС-2), а учитель видит, что стих сдан позже.
- **Учитель** может принять стих позже и устно на уроке — через исправление оценок (БП-12); результат тот же.
- **Лимиты.** Дневной лимит попыток (ВП-9) действует на каждый стих отдельно.

**ВП-17 Перевод и язык распознавания.** Язык распознавания речи и эталонный текст определяются языком группы (ЯГ-1). В попытке хранится перевод, по которому она проверялась (6.4): при смене языка группы (ЯГ-4) старые попытки не пересчитываются. Качество распознавания английской речи детей проверяется отдельно в тесте 6.2 (пороги для ru и en могут различаться — 12.3).

## 7. Достижения и штрафы → отдельный документ

Правила достижений и штрафов вынесены в **`achievements_spec.md`** (версия 1.0). Номера правил сохранены, ссылки ДС-… и ШТ-… в этом документе ведут туда. Кратко:

- **Принципы:** награждается усилие и постоянство; никаких автоматических потерь; никаких публичных рейтингов детей; мало достижений, уровни бронза / серебро / золото.
- **Одни и те же действия — одна награда (ДС-3, ДС-12):** каждая выдача хранит доказательства — записи проверки; запись не может быть использована дважды для одного достижения и уровня. Гарантируется ограничением уникальности данных.
- **Серии (ДС-1, ДС-11):** пропуски не рвут серию; одна серия — одна награда каждого уровня; после обрыва уровни можно получить снова. Серия, пересекающаяся с награждённой, — та же серия.
- **Ручная выдача (ДС-5, ДС-13):** для достижений с правилом учитель отмечает уроки, система предлагает последние подходящие.
- **Отзыв (ДС-7):** только admin; баллы снимаются, доказательства остаются занятыми.
- **Пересчёт (ДС-6):** по событию «проверка завершена», правке проверки, закрытию окна практики, закрытию года, включению режима; кнопка у admin.
- **Режим группы (ДС-14):** учитель включает и выключает достижения и штрафы; полученное сохраняется; уроки периода выключения — пропуск.
- **Обзорные уроки (ДС-15):** пропуск для серий по стихам и тестам, обычный факт для тетради.
- **Штрафы (ШТ-1…ШТ-10):** только вручную, с причиной, не больше значения каталога, один на ученика за урок, можно снять; уменьшают кирпичики, но не оценки и не аналитику.

## 8. Рейтинг

**РТ-1 Видимость (решение владельца).** Рейтинг видят **только teacher (своя группа) и admin (группа и школа)**. Родитель и ребёнок рейтинга и своего места в нём **не видят**.

**РТ-2 Назначение.** Рабочий инструмент: увидеть, кому нужна помощь и кого отметить, — не мотивационный механизм для детей.

**РТ-3 Что в основе.** Метрика рейтинга (сумма баллов за год, среднее, учёт редких посещений по БП-1) — **не определена** (Раздел 12, п. 5). Баллы-бонусы за достижения и штрафы (ШТ-1…ШТ-10) в рейтинг не входят, пока не решено иное; число штрафов учитель видит отдельной колонкой.

**РТ-4 Принцип для родителя.** Личная аналитика ребёнка показывает его собственную динамику, без места среди других детей и без сравнения с конкретными учениками.

**РТ-5 Проектор (решение владельца).** Рейтинг **не выводится на экран для класса** и не имеет режима публичного показа. В действующем приложении учитель показывал рейтинг детям — в новой системе этого сценария нет.

## 9. Аналитика и отчёты

### 9.1 Экран «Аналитика группы» *(по образцу отчёта прототипа)*

Для teacher (своя группа) и admin (любая группа, переключатель групп). Фильтр периода: учебный год (по умолчанию), месяц, произвольный диапазон.

**Ключевые цифры.** Не ряд одинаковых карточек, а иерархия: главная цифра — средняя посещаемость основной выборки; рядом компактной строкой — средние стихи / тест / тетрадь с числом наблюдений (N). Отдельной строкой — состав выборки: основная (A), исключены по явке (B), неактивные (C), без проверенных уроков после зачисления (D). Проценты — с одним знаком после запятой, средние — с одним-двумя.

**Удалённые данные (только admin).** Если в выбранном периоде были данные ребёнка, удалённые по запросу опекуна, — пометка «показатели пересчитаны после удаления данных по запросу опекуна, дата» (УД-7). Число таких детей не показывается, если их меньше трёх: иначе можно вычислить, чьи данные удалены.

**Качество данных (только admin).** Строка «пропущенных записей на проверенных уроках: N» (БП-1) и, для перенесённых данных, «удалено дублей: M» (Раздел 13). Это не ошибка ученика, а сигнал проверить журнал.

**Графики** (по урокам, ось X — даты уроков; только основная выборка, БП-1):
- **Посещаемость.** Одна ось: доля присутствующих от состава основной выборки на этот урок, %. Число детей — в подписи точки и во всплывающей подсказке. *В отчёте прототипа здесь было две оси Y (число и доля) — это заменено: две шкалы на одном графике читаются неверно.*
- **Среднее число рассказанных золотых стихов за урок** (БП-2): точка — урок, где рассказывали; первый урок года не участвует; среднее по ученикам основной выборки с валидным наблюдением.
- **Средний балл теста**, шкала 0–10 (БП-3): оценки при присутствии и «сдано позже». Обзорные уроки — без точки (тест не пишется), так же как на графике стихов.
- **Средний балл тетради**, шкала 0–10 (БП-4).
- *В старом приложении успеваемость и посещаемость были на одном графике с двумя осями Y. В новой системе это два отдельных графика.*
- Под каждым графиком — одна строка «как считали» (9.6).
- Наведение / нажатие на точку показывает значение, число наблюдений и дату. У каждого графика есть табличное представление («Показать таблицей»).

**Таблицы.**
- Основная выборка: ФИО, год рождения, явка (%), присутствовал / проверено, средние по стихам, тесту, тетради. Строка ведёт в карточку ученика.
- Исключённые из средних (явка ниже 50%): число занятий, проверенных уроков, явка.
- Неактивные ученики.
- Активные ученики без проверенных уроков после зачисления.
- Разрез по году рождения — описательно, только основная выборка, с оговоркой о малой выборке.

### 9.1.1 Экран «Аналитика ученика»

Для teacher (свои группы), admin (все), parent (только свой ребёнок, в упрощённом виде — 9.2).
- Статус в выборке и почему: «Учитывается в групповых средних: да / нет — явка 43%, ниже порога 50%» (слой A / B / C / D).
- Ключевые поля: год рождения, статус, явка «присутствовал из проверено», личные средние по стихам / тесту / тетради с N.
- Графики по урокам: присутствие (ступенчатый: был / не был), стихи за урок, балл теста, балл тетради.
- Таблица по урокам: дата, тема, присутствие, стихи «2 из 3», тест, тетрадь; оценки «сдано позже» помечены с датой сдачи; «тест не проводился» отличается от «нет оценки».
- Для учеников вне основной выборки — пометка, что личные средние не входят в групповые.
- Блок «Динамика успеваемости» (9.1.3).

### 9.1.3 Динамика успеваемости ребёнка (дифференциальное измерение)
Отвечает на вопрос «успеваемость растёт или падает?», а не «сколько баллов набрано».
1. **Нормированный балл за урок, %** = баллы урока / максимум, возможный на этом уроке, × 100. Максимум зависит от урока: 2 × число стихов к рассказу + тест (если проводился) + тетрадь + спевка, по весам группы. У обзорного урока максимум — тетрадь и спевка. Без нормирования урок без теста выглядел бы как падение.
2. Учитываются только проверенные записи. Урок без записи, а также урок, где ребёнок отсутствовал и ничего не сдал, — пропуск точки, а не ноль: пропуск — это посещаемость, а не успеваемость. «Сдано позже» входит (оценка относится к дате урока).
3. **Сглаживание** — скользящее среднее по 3 урокам (по имеющимся точкам). Один слабый урок не должен выглядеть как обвал.
4. **Изменение за урок** — разность соседних сглаженных значений, п.п. Это дискретная производная функции «баллы / урок». Показывается столбцами вокруг нуля: рост и снижение разными цветами и знаком «+ / −».
5. **Тренд** — наклон прямой (метод наименьших квадратов) по нормированным баллам за последние 6 уроков, п.п. за урок. Подпись: «растёт» при наклоне выше +1 п.п./урок, «снижается» — ниже −1, иначе «стабильно». Пороги — настройка (Раздел 12, п. 17). Для меньше чем 4 точек тренд не показывается: «мало данных».
6. Видят teacher и admin (карточка ученика) и parent (свой ребёнок). Родителю — без сравнения с другими детьми; при «снижается» — мягкая подсказка поговорить с учителем, а не оценка ребёнка.

### 9.1.4 Блок «Кто какие уроки провёл» (экран «Аналитика группы»)

Для teacher (своя группа) и admin (любая группа). Расположен под графиками, подчиняется фильтру периода (9.1).
- **Таблица по учителям группы:** учитель; сколько уроков провёл за период; из них обычных и обзорных; сколько запланировано (будущие уроки с этим ведущим); номера уроков со ссылкой на урок.
- Считаются проведённые уроки периода (с проверкой, 9.1 «проверенный урок»). Отменённые уроки — события календаря и уроков не создают (3.18). Учитель, назначенный на группу в этом году, но не ведший ни одного урока, показывается со строкой «0».
- Если среди ведущих есть учитель, чьё назначение снято (УЧ-4), он показывается с пометкой «уже не в группе».
- Назначение блока — справедливое распределение нагрузки и история («кто вёл урок про Иосифа»), а не оценка учителя. Ведущий не равен проверяющему (УЧ-3): блок не показывает, кто вносил оценки.
- Родителю блок не показывается.

### 9.1.2 Экран «Школа» (admin)

Сравнение групп: таблица (ученики основная / всего, посещаемость, средние, состояние проверки последнего урока) и график посещаемости по урокам — **по группе на линию**, не больше трёх-четырёх линий, с подписями у концов линий и легендой. Список «требует внимания».

### 9.2 Аналитика по ролям

**Admin:** школа в целом (сводно по группам), любая группа, любой ученик, любой пользователь; рейтинг школы и групп; мониторинг голосовой проверки (9.3).

**Teacher:** аналитика своей группы (9.1, включая «кто какие уроки провёл», 9.1.4); участие в голосовой практике (кто практиковался в текущем окне, кто нет); новые достижения; штрафы группы (действующие и снятые); баланс кирпичиков по группе (кому сколько осталось выдать); рейтинг группы.

**Parent:** только свой ребёнок (9.1.1 без статуса выборки и без групповых сравнений) — посещаемость за год, динамика баллов за стихи / тест / тетрадь, полученные достижения, штрафы с причиной и статусом (ШТ-8), баланс и история кирпичиков (набрано / выдано, в том числе бонус и штрафы), история голосовых попыток и прогресс в текущем окне («2 дня из 3»). Без рейтинга и без сравнения с другими детьми (РТ-4).

### 9.3 Метрики голосовой проверки (качество и использование)
- Доля детей, практиковавшихся в окне; среднее число разных дней практики
- Распределение итоговых баллов за стихи: авто vs вручную
- Доля попыток с ошибкой (тишина, неразборчиво, технический сбой)
- **Доля авто-оценок, переопределённых учителем вручную** — основной индикатор качества AI-оценки: рост этой доли означает, что пороги или модель нужно пересматривать

### 9.4 Метрики достижений и кирпичиков
- Выдано за период по категориям и уровням; доля ручных выдач
- Кирпичики: набрано / выдано / остаток по ученику и по группе; ученики с отрицательным остатком (БП-11)
- Дети без единого достижения за N уроков (кому нужно внимание)
- Штрафы за период: по видам, по учителям (перекос — один учитель штрафует в разы чаще других — повод для разговора, а не для настройки системы), доля снятых
- Дети с двумя и более действующими штрафами за месяц — сигнал поговорить с родителями, а не штрафовать дальше (только teacher и admin)

### 9.5 Требования к графикам
- Одна ось Y на график; две разные величины — два графика.
- Одна серия — одним цветом и без легенды (название в заголовке); несколько серий — легенда и подписи у линий.
- Цвет — не единственный носитель смысла: значения доступны подписью, подсказкой или таблицей.
- Тонкие линии, нулевая линия видна, сетка приглушённая; без 3D и без декоративных градиентов.
- Пустые состояния объясняют причину: «тест выключен в настройках группы», «нет наблюдений для основной выборки».
- Изменения вокруг нуля (9.1.3) — столбцы от нулевой линии, два цвета для роста и снижения плюс знак в подписи.

### 9.6 Требование к прозрачности методологии

Каждый отчёт сопровождается разделом «как мы считали цифры» (для блока 9.1.4: «считаются проведённые уроки периода по полю “Ведёт”, запланированные — отдельно»; включая строку «данные детей, удалённые по запросу опекунов, не учитываются») — правила из Раздела 5 простым языком для директора и церковного совета. Для голосовой проверки и достижений добавляются свои пояснения: как оценивается рассказывание стиха (правило окна и «N дней»), что означает «подряд» (пропуски не ломают серию), когда достижения выдаются автоматически и когда вручную.

### 12.2 Требуют решения до перехода к схеме БД

2. **Что parent может редактировать** (БП-9). Предложено: контакты, мед. данные, экстренный контакт, согласия; остальное — только чтение.
3. ~~Отец / мать / опекуны и сущность «семья»~~ — закрыт решениями 32 и 34.
4. **Метрика «стих выучен»** для достижений: максимальный балл (2) по умолчанию, порог параметризуется.
5. **Метрика рейтинга** (РТ-3): сумма баллов уроков за год, среднее или другое; включать ли учеников вне основной выборки БП-1.
6. ~~Формула баллов и пересчёт~~ (БП-5) — **решено 2026-10-10, вариант А:** итог записи = стихи × вес + тест × вес + тетрадь × вес + спевка (если была) × вес; веса по умолчанию 1; баллы **замораживаются** при выставлении (хранятся итог и снимок весов); смена весов действует на новые проверки; правка записи (БП-12) пересчитывает эту запись по текущим весам. Остаток: значение баллов за спевку по умолчанию (схема Q-08).
7. **БП-3 и БП-10:** правило «тест засчитывается, если был на следующем уроке» — только для отчётного среднего, не для баллов и кирпичиков (предложено).
8. ~~pointsValue достижений~~ — закрыт 10 октября: задаётся admin в каталоге; при ручной выдаче teacher может указать меньше, но не больше значения каталога.

Правила переноса:
- **Дубли записей** «урок × ученик»: остаётся одна — сначала запись с отметкой «ДЗ проверено», при равенстве — изменённая позже. Число удалённых дублей попадает в отчёт переноса и в строку качества данных (9.1).
- **Оценки за стихи:** в старом приложении поля «стих 1 / 2 / 3» записи урока N относятся к стихам урока N−1 (их рассказывают на уроке N), хотя в старом интерфейсе колонки подписаны стихами текущего урока. При переносе поле i записи урока N сопоставляется со стихом i урока N−1 (БП-2). *Подтвердить — Раздел 12, п. 15.*
- **Дата отсчёта** учеников — по правилу БП-1 для перенесённых данных.
- Каждая «сирота» (ссылка на несуществующего ученика, урок, группу) попадает в **отчёт**, а не молча отбрасывается; владелец решает по каждой.
- Проверка сходимости после переноса: число уроков, проверок, суммы баллов и выданных кирпичиков по ученику и году совпадают со старой системой.
- Перенос выполняется на копии; старое приложение остаётся рабочим до приёмки. Репетиция — на временной ветке базы, итоговый запуск — в prod (Раздел 15, ОК-6). Реальные данные детей в dev не загружаются (ОК-4).

## 14. Локализация интерфейса (решение владельца)

**ЛК-1 Никаких строк в коде.** Все тексты интерфейса — подписи, пункты меню, заголовки, кнопки, подсказки, пустые состояния, сообщения об ошибках и уведомления, тексты писем и дайджестов — хранятся только в словарях. Строка в JSX/TSX вместо ключа считается ошибкой и ловится линтером (например, правилом на «literal string» в JSX).

**ЛК-2 Словари по областям.** Словарь делится на пространства имён (namespaces):

| Namespace | Что внутри | Кто загружает |
|---|---|---|
| `common` | общая навигация и меню пользователя, общие кнопки (Сохранить, Отмена, Удалить), статусы, даты и числа, ошибки, пустые состояния, тексты, общие для нескольких ролей (урок, стих, кирпичики) | все страницы |
| `auth` | вход, регистрация, согласие на обработку ПД, экран заявки, профиль | страницы входа, регистрации, профиля |
| `teacher` | Сегодня, уроки, проверка ДЗ, состав группы, кирпичики, рейтинг | область учителя |
| `parent` | успехи ребёнка, стихи, данные и согласия | область родителя |
| `admin` | школа, заявки, пользователи, запросы на удаление, группы, учебный год, достижения и штрафы, настройки | область admin |
| `analytics` | графики, слои выборки, «как мы считали» | экраны аналитики (teacher, admin, parent) |

Строка, которая нужна двум областям, переезжает в `common` (или в общий namespace вроде `analytics`) — дублировать её в двух словарях нельзя.

**ЛК-3 Два языка с первого дня.** Каждый namespace существует в `ru` и `en`. Ключи одинаковые; словарь `en` проверяется типом словаря `ru` (TypeScript: `en` должен удовлетворять `typeof ru`) — пропущенный ключ — ошибка сборки, а не пустое место на экране.

**ЛК-4 Загрузка (Next.js, App Router).** Язык не входит в URL (он один на всё приложение, ЛК-7). Корневой layout на сервере читает язык из настроек приложения (с кешем и сбросом при изменении настройки) и загружает `common`; layout каждой области (`(teacher)`, `(parent)`, `(admin)`, `(auth)`) — свой namespace, через динамический `import()` JSON-файла. Серверные компоненты получают словарь напрямую; в клиентские компоненты передаётся **только нужное подмножество ключей**, а не весь словарь. Родитель никогда не скачивает словарь admin.

**ЛК-5 Формы слов и форматы.** Множественное число — через `Intl.PluralRules` (в русском формы one / few / many: «1 урок, 2 урока, 5 уроков»), ключи вида `lessons_count.one / .few / .many / .other`. Даты, числа и проценты — через `Intl.DateTimeFormat` и `Intl.NumberFormat` для выбранного языка, без ручной склейки. Подстановки — именованные: `"{name} получил {count} кирпичиков"`.

**ЛК-6 Что не переводится.** Содержимое, которое вводят люди или загружают скрипты: темы и планы уроков, тексты золотых стихов (перевод Библии по языку группы, ЯГ-1 и 3.10 — не по языку интерфейса), комментарии, названия групп. Названия и описания достижений и штрафов хранятся в каталоге на RU и EN (ДС-9) и показываются на языке приложения. Тексты согласий — отдельные версии на каждом языке.

**ЛК-7 Язык выбирает admin.** В настройках приложения (только admin): язык интерфейса — русский или английский, для всех пользователей. Изменение — запись в журнале; вступает в силу при следующей загрузке страницы. Личного выбора языка у пользователя нет (решение владельца).

**ЛК-8 Длина строк.** Английские и русские тексты разной длины; вёрстка рассчитана на +30% длины (DESIGN_SYSTEM.md). Проверка — снимки ключевых экранов на обоих языках в автотесте.

**ЛК-10 Тексты меняются только в коде (решение владельца).** Словари — часть исходного кода приложения: правка текста = изменение JSON-файла, ревью и деплой. Через интерфейс тексты не редактируются, переопределений в базе данных нет; admin выбирает только язык (ЛК-7). Исключение — пользовательское содержимое (ЛК-6): названия достижений и штрафов в каталоге, тексты согласий по версиям.

**ЛК-9 Структура файлов (ориентир).** `messages/ru/common.json`, `messages/ru/teacher.json`, … и такие же файлы в `messages/en/`; функция `getDictionary(locale, namespace)` на сервере; ключи — по экранам: `teacher.check.save_next`, `common.actions.cancel`.

## 15. Окружения: dev и prod (решение владельца)

Два окружения. Они не делят ни базу, ни учётные данные, ни секреты.

| | **dev** | **prod** |
|---|---|---|
| База данных | Neon, своя | Neon, своя |
| Содержимое после развёртывания | схема + справочники + **фейковые данные** | схема + справочники + первый admin; **больше ничего** |
| Пользователи и дети | вымышленные | только реальные: появляются через регистрацию и работу admin |
| Вход | отдельные приложения Google и Telegram-бот | свои |
| Назначение | разработка, показ, автотесты | работа школы |

**ОК-1 Раздельные базы и секреты.** У каждого окружения — своя база с отдельными строкой подключения и учётными данными, ключами Auth.js, приложениями Google и Telegram, хранилищем файлов (для голосовых записей — post-MVP). Окружение определяет переменная `APP_ENV` (`dev` / `prod`); при запуске приложение проверяет, что `APP_ENV` и строка подключения не противоречат друг другу, и не стартует при расхождении. *Один или два проекта Neon — 12.2 п. 34.*

**ОК-2 Prod — пустая база.** После развёртывания в prod есть только:
1. схема, созданная миграциями (полная схема сразу — `mvp_scope.md`);
2. **справочники**, без которых приложение не работает: книги и тексты Библии (3.10, ПБ-1), стартовый каталог достижений и штрафов (*12.2 п. 33*);
3. настройки приложения по умолчанию (язык интерфейса ru, ЛК-7);
4. первый admin (ОК-3).
Ни одной группы, ученика, семьи, урока, учебного года, проверки и кирпичика: их создают люди через приложение.

**ОК-3 Первый admin.** В пустом prod некому одобрить первую заявку (2.4). Поэтому email первого admin задаётся переменной окружения; первый вход с этим email создаёт активную учётную запись admin (один раз, запись в журнале, БП-8). Дальше роли назначает admin обычным путём. *Подтвердить — 12.2 п. 32.*

**ОК-4 Dev — фейковые данные из прототипа.** Данные для dev создаются позже (отдельный шаг после схемы БД); источник — рабочий прототип: группы, учителя, ученики, семьи, уроки с ведущими учителями, проверки, журнал кирпичиков, достижения и штрафы, календарь, заявки, запросы на удаление, журнал. Правила:
- **Только вымышленные люди.** Реальные данные детей и взрослых (из старого приложения, из prod, из копий prod) в dev не попадают никогда; дамп prod в dev не загружается. Согласие опекуна на данные ребёнка (2.6) на разработку не распространяется;
- данные берутся из **файла фикстур** в репозитории (JSON / TS, снятый с прототипа), а не из случайной генерации: два запуска дают одно и то же, скриншоты и тесты воспроизводимы;
- запуск — отдельная команда (`seed:dev`), идемпотентная: пересоздаёт данные dev с нуля;
- команда **отказывается работать**, если `APP_ENV` не равен `dev` или строка подключения не отмечена как dev (ОК-1) — защита от случайного запуска на prod.

**ОК-5 Что есть только в dev.** Переключатель роли «смотреть как» (как в прототипе) и сброс данных; включаются только при `APP_ENV=dev` и не попадают в сборку prod. *Подтвердить — 12.2 п. 35.*

**ОК-6 Миграции схемы и данных.** Файлы миграций одни для обоих окружений и применяются сначала в dev, потом в prod; ручных правок схемы в prod нет. Перенос данных из старого приложения (Раздел 13) репетируется на временной ветке базы, затем выполняется в prod; dev он не затрагивает.

**ОК-7 Справочники — в обоих окружениях.** Скрипты загрузки Библии (ПБ-1, ПБ-2) и seed справочников запускаются и в dev, и в prod и идемпотентны. Фейковые данные (ОК-4) — только в dev.

**ОК-8 Не усложнять.** Окружений ровно два. Staging, окружения под ветки и автоматическое копирование данных не нужны, пока нет пользователей и команды; возвращаемся к этому, когда появится причина.
