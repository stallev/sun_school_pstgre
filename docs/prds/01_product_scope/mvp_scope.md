## 1. Purpose

Зафиксировать состав MVP: что входит, что нет, какие временные правила действуют до post-MVP. Читают: авторы contracts, specs, задач фаз. Каждое требование имеет ID `PRD-<area>-NN`; задачи и контракты ссылаются на них. Признак **S** — затрагивает доступ или персональные данные (registry §2.3.2a).

## 2. Scope / Out of scope

**MVP заменяет действующее приложение для учителей и администратора.** Критерий готовности: реальная группа ведётся в новой системе (уроки, проверка ДЗ, кирпичики, аналитика), а старое приложение переведено в режим только для чтения.

**Не входит:** приложение для родителей, голосовая проверка стихов, достижения и штрафы (ни автоматически, ни вручную) — см. [`post_mvp_deferrals.md`](./post_mvp_deferrals.md).

## 4. Временные правила MVP

Действуют до волны 2 (семьи и родители).

| Ситуация | В MVP |
|----------|-------|
| Согласие на данные ребёнка | Бумажное: admin отмечает подписанта (текстом), дату, версию текста, где оригинал (СО-3) |
| Удаление данных ребёнка | Родитель обращается к admin; admin создаёт и выполняет запрос от имени родителя |
| Заявка от родителя | **Отклоняется** с причиной «доступ родителей откроется позже» (решение владельца 2026-10-10); после старта волны 2 пользователь подаёт заявку заново |
| Контакты родителей | Нет данных в старом приложении; подписант записывается текстом |
| Кирпичики | Только баллы уроков, без бонусов и штрафов |
| Достижения из старого приложения | В базе, в интерфейсе не показываются |

## 5. Схема БД «сразу целиком»

Схема создаётся одной миграцией по всей спецификации, включая post-MVP (С-1…С-7 interim; решение зафиксировано в [ADR-005](../07_governance/adr_005_schema_complete_post_mvp_tables.md)). Правила:

1. Зависимости направлены от post-MVP к MVP; код MVP не обязан заполнять таблицы post-MVP.
2. Ссылки MVP → post-MVP только необязательные (nullable).
3. Нет API и экранов для post-MVP; включение — флаги `features.achievements`, `features.parents`, `features.voice`, выключены по умолчанию.
4. Миграция заполняет таблицы post-MVP там, где есть данные (выданные достижения).
5. Схема меняется обычными миграциями.
6. Библия: таблицы — в первой миграции, тексты — идемпотентными скриптами ([`Bible/README.md`](../../my_specs/Bible/README.md)).

## 6. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Teacher ведёт группу целиком в новой системе | Уроки, проверка, кирпичики, аналитика работают без старого приложения |
| **N** | Действие с неактивным годом, чужой группой, превышением остатка | Отказ с понятным сообщением; данные не меняются |
| **S** | Доступ только по ролям; ПД ребёнка — по согласию; удаление — по запросу | Проверки на сервере; запись в журнале |
| **Drift** | MVP-код начинает зависеть от post-MVP таблиц | Запрещено правилом С-1; ловится review |
