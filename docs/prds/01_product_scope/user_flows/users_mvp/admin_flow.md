## 1. Purpose

Описать, что делает администратор школы в MVP, по шагам и с исходами. Читают: автор `pages_functional_spec`, UX-документов, контрактов и задач фаз. Права — канон в `authorization_matrix` (W5-02); здесь только ссылки.

## 2. Scope / Out of scope

**В scope:** вход и первый запуск, заявки и роли, пользователи, учебный год, группы и назначения, ученики и зачисление, согласие (бумажное), запросы на удаление, журнал изменений, школьная аналитика и рейтинг, настройки приложения.  
**Вне scope (post-MVP):** семьи и роль parent (`parent_flow` — по желанию), достижения и штрафы, голосовая проверка.

## 3. Definitions

Статусы учётной записи, роли, статусы заявки и запроса — enum-ы `@sunschool/domain` (источник — [`database_schema_v1.md`](../../../03_data_model/database_schema_v1.md) *(planned, W1-F6)*). Правила — спец. §2.4, §5.

## 4. Flows

### 4.1 Первый вход в prod (ОК-3)

| Шаг | Действие admin | Исход |
|-----|----------------|-------|
| 1 | Входит через Google или Telegram с email из переменной окружения | Создаётся активная учётная запись admin (один раз, запись в журнале) |
| 2 | Открывает «Школа» | Пустой экран с призывом создать учебный год |

*Negative:* email не совпал — пользователь проходит обычную регистрацию (§4.2 teacher_flow) и ждёт одобрения; в prod без admin работать нельзя — это проверка развёртывания, не пользовательский сценарий.

### 4.2 Заявки на доступ (РГ-4, 2.4)

| Шаг | Действие | Исход |
|-----|----------|-------|
| 1 | Открывает «Заявки на доступ» (число новых — в меню) | Список, старые сверху: ФИО, способ входа, дата и версия согласия, дней ожидания |
| 2 | Видит подсказку дубликата | Предлагается «Объединить» (§4.3) |
| 3 | Одобряет: выбирает роль `teacher` или `admin`; для teacher — группы на текущий год | Статус «Активна»; запись в журнале |
| 4 | Либо отклоняет с обязательной причиной | Статус «Отклонена»; причина видна пользователю |

*Negative:* роль не выбрана — кнопка неактивна; teacher без группы допустим только с предупреждением; снять роль `admin` у последнего admin или у себя нельзя.

### 4.3 Пользователи, отключение, объединение (2.4)

1. «Пользователи» → фильтр по статусу, поиск → профиль пользователя.
2. Admin правит ФИО (запись в журнале), роли, отключает доступ (вход блокируется, данные сохраняются).
3. «Объединить» дубликатов: выбирает основную запись; вход через второго провайдера переносится; запись в журнале.

*Negative:* отключение или снятие роли у последнего admin — отказ; объединение с самим собой — отказ.

### 4.4 Учебный год и группы (БП-6, 3.3–3.6)

| Шаг | Действие | Исход |
|-----|----------|-------|
| 1 | «Учебный год» → создать и активировать год | Единственный активный год; уроки можно создавать |
| 2 | «Группы» → создать группу: название, язык группы (ru / en), настройки оценивания | Группа активна; язык определяет перевод Библии (ЯГ-1) |
| 3 | Назначает учителей на группу на год | Teacher видит группу |
| 4 | В конце года «Закрыть год» | Данные года — только чтение для teacher; admin правит с причиной и записью в журнал |

*Negative:* английский язык недоступен, пока перевод не «готов» (ЯГ-3); второй активный год — отказ; смена языка группы показывает предупреждение (ЯГ-4).

### 4.5 Ученики и зачисление (3.7–3.8, БП-7, СО-3, СО-4)

1. «Ученики и семьи» → карточка ученика (ФИО и данные).
2. Отмечает **бумажное согласие** опекуна (опекун, дата, версия текста, где оригинал) — запись в журнале.
3. Зачисляет ученика в группу; переводит между группами; исключает; оставляет «без группы».

*Negative:* зачислить без согласия нельзя (СО-4); перевод сохраняет историю зачислений.

### 4.6 Запросы на удаление (УД-1…УД-11)

1. «Запросы на удаление» → вкладки «Открытые», «Выполненные», «Отклонённые и отменённые».
2. По устному или письменному обращению опекуна admin **создаёт** запрос на удаление данных ребёнка (в MVP у опекунов нет учётных записей).
3. Перед выполнением видит план: сколько записей удалится, сколько обезличится; подтверждает вводом слова «удалить».
4. Либо отклоняет с обязательной причиной, видимой автору.

*Negative:* срок — 15 календарных дней, просрочка подсвечена (УД-5); запрос последнего admin не выполняется, пока нет другого admin (УД-9).

### 4.7 Журнал, аналитика, настройки

| Раздел | Действие | Исход |
|--------|----------|-------|
| «Журнал изменений» | Просмотр и фильтр (только admin) | Записи неизменяемы (БП-8) |
| «Школа», «Аналитика», «Рейтинг» | Просмотр по школе и любой группе | Средние по БП-1; строка качества данных |
| «Настройки приложения» | Язык интерфейса ru / en | Применяется ко всем пользователям (ЛК-7) |

## 5. Security paths (ссылки)

Все операции — только для роли `admin`; проверка на сервере (security floor). Детали: `authorization_matrix` *(planned, W5-02)*, `access_requests_and_roles_contract` *(planned, W8-03)*, `deletion_requests_contract` *(planned, W8-08)*. Пользователь без одобренной заявки не видит ничего, кроме регистрации (РГ-1).
