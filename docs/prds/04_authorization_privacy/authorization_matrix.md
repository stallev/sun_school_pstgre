## 1. Purpose

**Единственный** канон прав: кто и что может делать в MVP. Контракты W8, спецификации W9 и тесты `policy` ссылаются на строки `AZ-NN` и не пересказывают правила. Читают: авторы контрактов, исполнители, `reviewer` (путь S).

## 2. Scope / Out of scope

**В scope:** проверка доступа по статусу учётной записи, роли и принадлежности ресурса; поведение отказов; защиты от повышения прав.  
**Вне scope:** механизм входа и сессии ([`auth_runtime_spec.md`](../05_runtime/auth_runtime_spec.md)); сценарии мутаций (W8); права роли `PARENT` и таблиц post-MVP — перечислены в §7 как справка, MVP их не реализует.

## 3. Definitions

| Термин | Значение |
|--------|----------|
| Статус | `ACCOUNT_STATUS`: `REGISTRATION`, `REQUEST_PENDING`, `REJECTED`, `ACTIVE`, `DISABLED`, `DELETED` (`app_user.status`) |
| Роль | `USER_ROLE`: `ADMIN`, `TEACHER` (в MVP); `PARENT` не выдаётся. Роли есть только у `ACTIVE` |
| «Свой» ресурс (teacher) | Ресурс группы `G` и учебного года `Y`, если есть `teacher_assignment (user_id, G, Y)`. «Своя группа» без указания года — назначение в **активном** году |
| Активный / закрытый год | `academic_year.status` = `ACTIVE` / `CLOSED` (БП-6). Закрытый год для teacher — только чтение |
| Серверная проверка | Чтение статуса и ролей по БД в `policy-server`, не из JWT (ADR-003 §4.3) |

## 4. Слои проверки

| Слой | Что проверяет | Источник данных | Назначение |
|------|---------------|-----------------|------------|
| `proxy.ts` / `policy-edge` | Есть ли сессия; статус и роль **по префиксу маршрута** | JWT (`uid`, `status`, `roles`) | Оптимистичные перенаправления, без DB |
| Страница / Server Action / Route Handler | Статус, роль, принадлежность по БД | `policy-server` | **Окончательное** решение |
| DAL | Фильтр выборки по `gradeId` / `academicYearId` | запрос | Чужие данные не читаются, даже при ошибке слоя выше |

Скрытие пункта меню — не защита ([`responsive_navigation_contract.md`](../../design/responsive_navigation_contract.md) §7).

## 5. Правила отказа

| ID | Ситуация | Результат |
|----|----------|-----------|
| **AZ-D1** | Нет сессии | Перенаправление на `/login` |
| **AZ-D2** | Статус не допускает маршрут (§6) | Перенаправление на домашний маршрут статуса (§6) |
| **AZ-D3** | Статус `ACTIVE`, но роль не подходит маршруту | Экран «Нет доступа» (403), навигация роли сохраняется |
| **AZ-D4** | Ресурс чужой (чужая группа, год, ученик) или не существует | **404**, без различия «нет» и «чужой» — существование не раскрывается |
| **AZ-D5** | Мутация вне прав, роль/статус изменились после выдачи JWT | Отказ `FORBIDDEN`; данные не меняются; JWT не обновляется |
| **AZ-D6** | Действие нарушает инвариант (последний admin, закрытый год) | Отказ с кодом домена; данные не меняются |

Коды отказов — константы `@sunschool/domain` (`MUTATION_ERROR_CODES`: `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION`, `CONFLICT`); тексты — по ключу `common`/`auth` словаря (ADR-008). Новый код сначала добавляется в домен.

## 6. Статус × маршрут

`✔` — доступен; `→ X` — перенаправление на `X`; `—` — только в рамках статуса ниже. Список маршрутов — [`canonical_routes.md`](../../design/canonical_routes.md) §4, здесь не дублируется.

| Статус | `/login` | `/privacy` | `/register` | `/pending` | `/profile` | Остальные `(app)` |
|--------|----------|------------|-------------|------------|------------|-------------------|
| нет сессии | ✔ | ✔ | → `/login` | → `/login` | → `/login` | → `/login` |
| `REGISTRATION` | → `/register` | ✔ | ✔ | → `/register` | → `/register` | → `/register` (РГ-1) |
| `REQUEST_PENDING` | → `/pending` | ✔ | → `/pending` | ✔ | ✔ | → `/pending` |
| `REJECTED` | → `/pending` | ✔ | → `/pending` | ✔ | ✔ | → `/pending` |
| `ACTIVE` | → домой (`/today`, `/school`) | ✔ | → домой¹ | → домой | ✔ | по роли (§8) |
| `DISABLED` | ✔ (вход отклонён, сообщение) | ✔ | → `/login` | → `/login` | → `/login` | → `/login` |
| `DELETED` | ✔ (вход отклонён) | ✔ | → `/login` | → `/login` | → `/login` | → `/login` |

¹ Исключение — устаревшая версия согласия (РГ-5): см. Q-02.

Домашний маршрут: `TEACHER` → `/today`; `ADMIN` → `/school`. Если у пользователя обе роли, приоритет у `ADMIN` (`/school`); переключателя роли в MVP нет.

## 8. Маршрут × роль

Роль-кандидаты по маршрутам — в [`canonical_routes.md`](../../design/canonical_routes.md) §4; эта матрица их **подтверждает**, а не копирует. Контроль при несоответствии — AZ-D3 (403). Дополнительные правила:

1. Маршруты, привязанные к «моей группе» (`/today`, `/lessons`, `/check`, `/group`) — только `TEACHER`; `ADMIN` получает AZ-D3. Страницы конкретного урока (`/lessons/new`, `/lessons/[lessonId]*`) доступны и `ADMIN` (AZ-30…AZ-35: создание, правка, корректировка по спец. §2.2) — по прямой ссылке, из аналитики и журнала; пунктов меню Teacher у admin нет (точка входа — Q-04).
2. Группа Admin (`/school`, `/approvals`, `/users*`, `/people`, `/groups*`, `/year`, `/deletions`, `/audit`, `/settings`, `/achievements`) — только `ADMIN`. `/achievements` существует при включённом `features.achievements`; при выключенном флаге маршрут отвечает 404. Teacher на `/achievements` — AZ-D3.
3. Общие (`/calendar`, `/rating`, `/verses`, `/analytics*`, `/bricks`, `/profile`) — `TEACHER` и `ADMIN`; объём данных определяют §7.
4. Параметр маршрута (`[lessonId]`, `[pupilId]`, `[groupId]`, `[userId]`) проверяется как ресурс (AZ-D4), не только как путь.
5. Волна 2 при `features.parents = true` (после переноса в §4, P13 CU11): `/family` — только `ADMIN`; `/child`, `/child/data`, `/child/consent` — только `PARENT`. `/calendar` для `PARENT` — чтение событий групп своих детей. При выключенном флаге эти маршруты отвечают 404. `/verse*` остаются волной 3.

## 9. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Teacher открывает урок своей группы в активном году | Страница открыта; данные только его группы |
| **H** | Admin одобряет заявку, назначает `TEACHER` и группы на год | Статус `ACTIVE`, роль и назначения созданы, запись в журнале |
| **N** | Teacher открывает `/lessons/[id]` урока чужой группы | 404 (AZ-D4); данные не раскрыты |
| **N** | Teacher открывает `/users` | «Нет доступа» (403, AZ-D3) |
| **N** | Teacher правит проверку в закрытом году | Отказ AZ-P5; данные не меняются |
| **N** | Пользователь `REQUEST_PENDING` открывает `/today` | Перенаправление на `/pending` |
| **S** | Клиент передаёт `userId` или `gradeId` чужой | Игнорируется / 404; идентификатор субъекта берётся только из сессии |
| **S** | Роль teacher снята админом, JWT ещё жив | Первая серверная проверка отказывает; оптимистичный `proxy.ts` может пропустить страницу, но не данные |
| **S** | Admin пытается снять `ADMIN` с себя | AZ-P2, отказ |
| **Race** | Два admin одновременно снимают `ADMIN` у двух последних | Блокировка строк (R-8): успешна одна операция |
| **Drift** | Новая мутация без строки в §7 | Review: blocker (пропущенный путь S) |

## 10. Acceptance criteria

- [ ] Каждый маршрут `canonical_routes.md` §4 имеет подтверждение роли в §6 или §8 — исход: нет маршрута без правила.
- [ ] Каждая мутация MVP из контрактов W8 ссылается на строку `AZ-NN` — исход: нет ссылок на несуществующие ID.
- [ ] Тест policy для TEACHER: чужая группа → 404, чужая роль → 403, закрытый год → отказ — исход: unit-тесты `policy-server`.
- [ ] Teacher после снятия роли теряет доступ без повторного входа — исход: тест AZ-D5.
- [ ] Строки голоса не создают маршрутов — исход: `/verse*` остаются в `canonical_routes.md` §5. Маршруты волны 2 появляются в §4 только задачей P13 CU11 и только при флаге.

## 13. Agent notes

- Не проверять права по JWT при чтении или записи данных — только по БД (`policy-server`).
