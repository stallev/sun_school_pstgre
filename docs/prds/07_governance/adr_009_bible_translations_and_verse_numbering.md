## 1. Purpose

Зафиксировать, в какой нумерации хранятся золотые стихи, как к ней приводятся переводы, и что делать с английским переводом, лицензия которого не позволяет загрузку в приложение. Читают: авторы схемы, `bible_seed_contract`, форм урока.

## 2. Context

- В seed-данных два издания: RST (русский Синодальный, 31 166 стихов) и NIV (английский, 31 103 стиха). Книги и их порядок совпадают (66).
- **Нумерации расходятся в 165 из 1189 глав** (подсчёт по `verses_count`):

| Книга | Глав с расхождением | Пример RST / NIV |
|-------|--------------------:|------------------|
| Псалмы | 138 из 150 | гл. 3: 9 / 8 · гл. 9: 39 / 20 · гл. 10: 7 / 18 |
| Иов | 3 | гл. 39: 35 / 30 · гл. 41: 26 / 34 |
| Числа | 4 | гл. 29: 39 / 40 |
| 1 Царств | 3 | гл. 20: 43 / 42 |
| Нав, Еккл, Песн, Дан, Ос, Ион, Рим | по 2 | Рим 14: 26 / 23 |
| Лев, Деян, 2 Кор | по 1 | Лев 14: 56 / 57 |

- Помимо числа стихов в Псалмах сдвинут номер главы: Синодальный Пс. 22 («Господь — Пастырь мой») — это Ps. 23 в NIV; надписания псалмов в RST считаются стихом, в английских изданиях — нет.
- Прототип и действующее приложение ссылаются на стихи по-русски («Пс. 18:2»); золотые стихи вводят русскоязычные admin и teacher.

## 3. Decision

### 3.1 Общая нумерация — Синодальная (RST)

Золотой стих (`golden_verse`) хранит диапазон **в нумерации Синодального перевода**. Любой другой перевод приводится к ней таблицей соответствия.

Почему RST: (1) ссылки вводят и читают русскоязычные пользователи; (2) все существующие золотые стихи в прототипе и старом приложении — в этой нумерации, миграции ссылок не нужно; (3) RST в общественном достоянии и загружен целиком; (4) обратное — хранить в английской нумерации — потребовало бы переводить все существующие ссылки.

### 3.2 Английский перевод: NIV не загружается без лицензии

| Факт | Источник |
|------|----------|
| NIV защищён авторским правом (© 1973, 1978, 1984, 2011 Biblica, Inc.); не общественное достояние | biblica.com |
| Без письменного разрешения допускается цитирование до 500 стихов, не целая книга и не ≥ 25 % (по HarperCollins — также не ≥ 50 % книги) произведения; обязателен копирайт-текст | biblica.com/permissions, harpercollinschristian.com |
| Хранение и показ полного текста (31 103 стиха) в приложении этим не покрывается; нужна лицензия Biblica (США и Канада — Zondervan / HarperCollins Christian; Великобритания, ЕС — Hodder & Stoughton) | те же источники; вывод — оценка, не заключение юриста |

**Решение:** NIV остаётся локальным файлом разработчика (`.gitignore`), в dev и prod не загружается, пока владелец не получит лицензию. В качестве английского перевода по умолчанию **рекомендуется Berean Standard Bible (BSB)** — общественное достояние с 30 апреля 2023, разрешены любые использования; запасной вариант — World English Bible (WEB, общественное достояние; «World English Bible» — торговая марка eBible.org, текст менять нельзя). Выбор — владелец (Q-01). До выбора группа с языком `EN` недоступна (ЯГ-3), приложение работает на ru.

### 3.3 Таблица соответствия `bible_verse_map` — нужна, хранит только исключения

- Строка таблицы: `(translation_id, book_id, chapter_number, verse_number) → (common_chapter, common_verse)`; у стихов-надписаний, не имеющих отдельного номера в переводе, — `verse_number = 0` (Q-03).
- **Нет строки = нумерации совпадают** (тождество). Таблица заполняется только для 165 глав выше.
- Для Псалмов соответствие строится по правилу (сдвиг главы и количество надписаний выводятся из разности `verses_count`), исключения (слияния и разбиения псалмов, например Пс. 9–10, где счёт стихов расходится 39 / 20 и 7 / 18; полный список выявляет сверка счётчиков) — вручную; для остальных 27 глав — вручную по опубликованной таблице версификации.
- Таблица — данные, не код: хранится в репозитории как JSON, загружается тем же идемпотентным скриптом, что тексты (`bible_seed_contract`, W8-09).

### 3.4 Правила приложения (MUST)

1. Форма золотого стиха: ссылка вводится в RST-нумерации; показывается в переводе группы.
2. Сборка текста для группы: для каждого стиха диапазона берётся строка `bible_verse_map` перевода группы либо тождество; нет стиха — урок не сохраняется, форма показывает недостающие (ПБ-5).
3. Если диапазон касается главы с расхождением, а строк `bible_verse_map` для неё нет — сохранение запрещено; это ошибка данных, а не пользователя.
4. Ссылка у использованного золотого стиха не меняется (спец. 3.10).

## 4. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Teacher вводит «Пс. 22:1–3», группа `RU` | Текст из RST; для группы `EN` — через `bible_verse_map` стихи Ps. 23:1–3 |
| **N** | Диапазон попадает в главу с расхождением без строк карты | Сохранение отклонено; сообщение «нет соответствия в переводе» (ключ в messages); данные не меняются |
| **N** | Перевод группы не `READY` | Язык недоступен (ЯГ-3) |
| **S** | Загрузка защищённого лицензией текста без лицензии | Запрещено; NIV вне git и вне prod; проверка в `bible_seed_contract` по полю `license` |
| **Drift** | Карта и тексты разошлись после повторной загрузки | Скрипт сверяет суммы по главам и сообщает расхождения (ПБ-2) |

## 5. Rejected alternatives

| Альтернатива | Почему отклонена |
|--------------|------------------|
| Общая нумерация — английская | Все существующие ссылки — Синодальные; потребовался бы перевод ссылок и риск ошибок в Псалмах |
| Хранить золотой стих отдельно для каждого перевода | Нарушает спец. 3.10 («справочник общий, не дублируется по переводам») |
| Автосопоставление по тексту | Тексты на разных языках; невозможно проверить автоматически |
| Загрузить NIV «временно» в dev | Копия лицензированного текста всё равно распространяется через репозиторий и сборки; локально — допустимо, в git и в окружения — нет |

## 6. Consequences

- `bible_verse_map` обязательна в схеме (см. [`database_schema_v1.md`](../03_data_model/database_schema_v1.md) §5.4) и в `bible_seed_contract`.
- Скрипты загрузки приводятся к модели схемы: общий `bible_book`, перевод и стихи по переводам.
- До выбора английского перевода MVP работает на русском тексте; английский вход в prod блокируется статусом `NO_DATA`.
- Проверка соответствия — обязательный шаг до загрузки в prod: проверить на всех золотых стихах прототипа и старого приложения (спец. 12.2 п. 29).

## 7. Acceptance criteria

- [ ] Все 165 глав с расхождением перечислены в данных карты или явно помечены «без соответствия» — исход: скрипт загрузки печатает пустой список непокрытых глав.
- [ ] Сумма стихов по главе в `bible_verse_map` совпадает с `verses_count` перевода — исход: проверка в скрипте проходит.
- [ ] Для каждого золотого стиха из прототипа (`VERSES`) текст в RST и в английском переводе совпадает по смыслу — исход: ручная сверка владельцем, отмечена в `seed_data_spec`.
