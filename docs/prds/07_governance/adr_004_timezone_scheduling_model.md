# ADR-004 — Часовой пояс школы и работа с датами

**Тип:** ADR  
**Статус:** ACCEPTED  
**Версия:** 1.0  
**Дата:** 2026-10-11  
**Волна:** W4-02  
**Зависит от:** [`domain_invariants.md`](../02_domain_model/domain_invariants.md) INV-03, INV-13, INV-14, [`lifecycle_models.md`](../02_domain_model/lifecycle_models.md) §5.7, [`database_schema_v1.md`](../03_data_model/database_schema_v1.md) §3, §5.5–5.6  
**Связанные документы:** [`adr_001_stack_and_runtime.md`](./adr_001_stack_and_runtime.md), [`architecture_master_index.md`](../architecture_master_index.md), [`admin_flow.md`](../01_product_scope/user_flows/users_mvp/admin_flow.md)  
**Проверено по:** `Intl.DateTimeFormat` с `timeZone` (IANA) и `Intl.supportedValuesOf("timeZone")` — спецификация ECMAScript Intl, поведение известно, пересверка по MDN при P01; Next.js / Prisma / Neon не затрагиваются (хранение `timestamptz`, `date` — стандарт PostgreSQL).

---

## 1. Purpose

Определить, в каком часовом поясе трактуются даты и моменты, чтобы правило «сдано позже» (спец. §3.12), «Сегодня», календарь и журнал давали одинаковый результат у всех пользователей.

## 2. Scope / Out of scope

**В scope:** хранение дат и моментов, пояс школы, где он применяется.  
**Вне scope:** язык интерфейса ([ADR-008](./adr_008_i18n_ru_en_dictionary_slices.md)), расписание фоновых задач (их нет в MVP).

## 3. Context

- Даты уроков и событий — календарные дни, без времени (воскресенья).
- «Сдано позже» вычисляется: оценка выставлена **после даты следующего урока группы** (3.12). Сравнивается момент выставления (`timestamptz`) с календарной датой, поэтому нужен пояс, в котором «день» заканчивается.
- Школа одна; пользователи работают из одного региона, но часовой пояс браузера нельзя считать надёжным (путешествия, VPN).

## 4. Decision

| # | Решение |
|---|---------|
| 1 | Единый **пояс школы** `school_timezone` (IANA-имя) хранится в `app_setting`; значение выбирает **admin в «Настройках приложения»** (`/settings`), в коде не зашивается (решение владельца 2026-10-11) |
| 2 | Даты уроков, событий, границы учебного года — тип `date`, без времени и без пояса |
| 3 | Моменты (`checked_at`, `scored_at`, журнал, заявки) — `timestamptz`, хранятся в UTC |
| 4 | «Сегодня», календарь, подсветка просрочки (15 дней УД-5), отображение моментов — в поясе школы |
| 5 | «Сдано позже» = дата момента выставления **в поясе школы** > даты следующего урока группы; вычисляется при записи и сохраняется в `late` |
| 6 | До первого выбора действует `UTC`; admin видит предупреждение на экранах «Школа» и «Настройки» |
| 7 | Смена пояса не пересчитывает `late` и баллы ранее выставленных записей (INV-13) |
| 8 | Список допустимых поясов — полный IANA через `Intl.supportedValuesOf("timeZone")`; в интерфейсе — поиск по названию |

## 5. Rejected alternatives

| Альтернатива | Почему отклонена |
|--------------|------------------|
| Пояс браузера пользователя | Один и тот же момент даёт разный «день» у разных пользователей; «сдано позже» нестабильно |
| Пояс сервера (Vercel, UTC) | День заканчивается в 03:00 по Москве, не в полночь; ложные «сдано позже» |
| Пояс на группу | Школа одна; лишняя настройка |
| Зашить пояс в код | Решение владельца: выбирается в интерфейсе |
| Хранить моменты в локальном времени | Неоднозначность при переходе на летнее время |

## 6. Consequences

- В `database_schema_v1.md` §5.6 добавлен ключ `app_setting.school_timezone`.
- INV-03 в `domain_invariants.md` снимает оговорку «до решения ADR-004».
- Экран «Настройки приложения» получает второй параметр (помимо языка).
- Для миграции старые даты загружаются как `date`; моменты без пояса интерпретируются в поясе школы.
- Тесты `domain` для `late`: границы полуночи, переход на летнее время, смена пояса.

## 7. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Teacher выставляет оценку в 23:30 по поясу школы за день до урока | `late = false` |
| **H** | То же в 00:30 после даты следующего урока | `late = true`, «сдано позже» |
| **N** | Пояс не выбран | Действует UTC, у admin предупреждение; блокировки нет |
| **N** | Передано неизвестное IANA-имя | Отклонено валидацией, значение не меняется |
| **S** | Пояс меняет только `ADMIN`; запись в журнале | `TEACHER` не видит поле как редактируемое |
| **Drift** | Код использует `Date.now()` без пояса школы | Review и тест границ полуночи |

## 9. Acceptance criteria

- [ ] Ключ `school_timezone` есть в схеме и валидируется списком IANA — исход: тест валидации.
- [ ] Оценка в 23:59 и 00:01 по поясу школы относительно даты урока даёт разный `late` — исход: unit-тест `domain`.
- [ ] Смена пояса не меняет `late` и `points_total` существующих записей — исход: тест.
- [ ] Предупреждение admin показывается, пока пояс не выбран — исход: ручной шаг.

- Не пересчитывать `late` при смене пояса.
