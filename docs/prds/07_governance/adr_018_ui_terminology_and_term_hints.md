## 1. Purpose

Аудит стенда показал, что часть экранов написана языком аналитика и разработчика: «основная выборка», «N=26», «п. п.», «IANA-имя пояса (ADR-004)», «Спевка», «не ставил», «кирпичики» без определения. Пользователь (учитель, администратор) должен понять экран с первого взгляда, не читая сноски в конце страницы. Нужно одно решение для терминов, подсказок и форматов чисел и дат.

## 2. Scope / Out of scope

**В scope:** словарь терминов пользовательского интерфейса, паттерн подсказки `TermHint`, правила форматов (проценты, дробные числа, даты, шкалы), поведение переключателя «Смотреть как».  
**Вне scope:** расчётные правила аналитики (БП-1, БП-2, пороги 50% / N / M не меняются), схема БД, права доступа, палитра и шрифты (UX-03 без изменений), английские строки меняются по тем же ключам, но их перевод — задача CU соответствующей фазы.

## 3. Context

- В продуктовом тексте встречаются термины из статистики и внутренней документации; пояснения лежат сносками под таблицей (`analytics.json` «Как мы считали цифры»).
- Нет паттерна подсказки: на экранах только `title=` и мелкий серый текст.
- Форматы разнородны: даты «1 окт. 2026 г.», «4 октября», «2026-10-04», «11/3/2026» (`toLocaleDateString()` без локали); дроби «1.9» и «0,3» в одной таблице; доля 0–1 выводится с «%» (`0.8%` вместо `80%`).
- Переключатель «Смотреть как» хранится в `useState` и сбрасывается при перезагрузке; подпись роли в шапке берётся из реальной роли; пункты меню предпросмотра могут вести на страницы, закрытые реальной ролью (`/group` требует TEACHER).

## 4. Decision

1. **Словарь терминов (было → стало).**

   | Было | Стало | Где |
   |------|-------|-----|
   | основная выборка | **регулярно ходят** (дети, которые были не менее чем на половине проверенных уроков) | аналитика, школа |
   | реже 50% | **ходят редко** | аналитика |
   | N=26 / (N=4) | **26 детей** / **по 4 урокам** | KPI, таблицы |
   | п. п. | **«+1% к прошлому году»**, «без изменений» | сравнение лет |
   | Был / проверено | **Был на уроках** («5 из 5») | таблица учеников |
   | Явка % | **Явка** (значение в процентах: `80%`) | таблицы |
   | Качество данных: пропущенных записей… | **«У N учеников нет отметки на проверенных уроках»** + действие «Показать, кого» | аналитика |
   | Последний урок («Проверено 10 из 30») | **Проверка последнего урока** («10 из 30 проверено») | `/school` |
   | IANA-имя пояса (ADR-004) | **Часовой пояс школы**, выбор «Москва (UTC+3)» | `/settings` |
   | Рабочий инструмент: кому нужна помощь… | **Кто лидирует и кому нужна помощь** | `/rating` |
   | Спевка | **Пел вместе с хором** (подсказка) | проверка ДЗ |
   | не ставил | **Не отвечал** | проверка ДЗ |
   | заполнено 0 из 5 | **Заполнено полей: 0 из 5** | проверка ДЗ |

   Термин «кирпичик» определяется один раз в глоссарии и подсказке: «Внутренняя награда ученика: начисляются за баллы на уроках и достижения, штрафы уменьшают».

2. **`TermHint`.** Иконка «?» (`CircleHelp`, `aria-label` = название термина) рядом с заголовком колонки, метрики или секции; по клику / Enter — popover (`@base-ui/react/popover`) с 1–2 предложениями и ссылкой «Подробнее» (необязательно). Закрытие Esc и кликом вне; текст не длиннее 200 знаков; не заменяет подпись, а дополняет её. Тексты — только `@/lib/messages` (срез словаря маршрута), глоссарий терминов — один модуль `glossary`. Компонент добавляется в Design Lab раньше использования на экране (C-2).
3. **Форматы.** Проценты — целое с `%` (`86%`); доля 0–1 домен отдаёт как есть, умножение на 100 — в одном форматтере; баллы — «значение из максимума» (`6,3 из 10`); десятичный разделитель — по локали через `lib/i18n/format.ts` (запятая в ru), не `toFixed` + шаблон; даты — «4 окт. 2026» (`formatDate`), `toLocaleDateString()` без локали запрещён; каждая метрика — «значение + единица + база».
4. **Сноски → подсказки.** Объяснение метрики стоит у метрики (`TermHint`), а не абзацем в конце страницы; блок «Как мы считали цифры» сворачивается (`details`) и остаётся для тех, кто хочет подробности.
5. **Стоп-слова.** В `apps/web/src/lib/messages/ru/*.json` запрещены: `выборка`, `N=`, `п. п.`, `IANA`, `ADR`, `LEGACY`, `DTO`; проверяет vitest-тест по словарю (в `en` — `sample`, `N=`, `IANA`, `ADR`). Исключения перечисляются в тесте с причиной.
6. **«Смотреть как».** Выбранная роль предпросмотра хранится в cookie `view_as` (UI-предпочтение, `Path=/`, `SameSite=Lax`, не auth); сервер читает её только для набора пунктов меню и бейджа «Режим: учитель» в шапке; **права не меняются** — доступ решает реальная роль. Пункты предпросмотра, на которые у реальной роли нет доступа, не показываются; если их нет совсем — подсказка «Для режима учителя назначьте себя на группу». Видим только при `APP_ENV=dev` (как сейчас).
7. **Ошибка страницы.** Страница ошибки показывает причину человеческими словами, кнопку «Повторить», ссылку «На главную» и короткий код (digest) для администратора; событие уходит в Sentry. Клиентская ошибка в production не содержит текста серверного исключения (в Sentry — digest без прикладного стека, issue `SUN_SCHOOL_POSTGRES_DEV-3`), поэтому digest — единственная связка с серверным событием.
8. **Словарь и props (Sentry 2026-11-03).** Каждый ключ, который код достаёт из словаря по значению домена (`AUDIT_ENTITY_TYPE`, `AUDIT_ACTION`, статусы), покрыт тестом паритета домен ↔ ru/en; подписи по значению домена собираются безопасным хелпером (`safeAdminMessage(...) ?? значение`), а `getMessage` остаётся для статических ключей. В props `"use client"`-компонентов — только строки и сериализуемые объекты, не функции-форматтеры (`ui-messages-bundle-splitting` §3).

## 5. Rejected alternatives

| Вариант | Почему отклонён |
|---------|-----------------|
| Оставить «основная выборка» и добавить подсказку | Термин остаётся первым, что видит пользователь; подсказка не читается с первого взгляда |
| Заменить на «выборка — это дети…» в сноске | Сноска внизу страницы — ровно то, что аудит назвал проблемой |
| Нативный `title=` как подсказка | Не работает на касании, не читается скринридером как описание термина, не стилизуется |
| Tooltip по наведению | Не работает на мобильных; popover по клику доступен всем |
| Хранить «Смотреть как» в `localStorage` | Сервер не знает режим → мигание меню, расхождение с серверным набором пунктов |
| Менять реальные права при «Смотреть как» | Нарушает AZ: права определяются только ролью пользователя |

## 6. Consequences

- `analytics_screens_spec` и `sunday_school_data_analytics_spec`: «основная выборка» остаётся как доменный слой A в разделах расчёта (§БП-1), а пользовательское название — «регулярно ходят»; в тексте интерфейса домен-термин не используется.
- `design_system_lab_spec` +`TermHint`; `visual_identity_contract` +рецепт подсказки; `typography_text_guidelines` +раздел «Термины и подсказки»; `global_shell_spec` +режим «Смотреть как» и бейдж; `ui_states_contract` +страница ошибки с действием.
- Захардкоженные «N=» в JSX (`AnalyticsPeriodKpiSection`, `PupilAnalyticsKpiSection`) переносятся в словарь.
- Новая cookie `view_as` — UI-предпочтение, как `sidebar_collapsed` (ADR-017); не auth-cookie.
- Прототип и parity-строки обновлены в подготовке P25.

## 7. Paths (H / N / S)

**H:** учитель открывает аналитику и понимает «Регулярно ходят 26 из 30» без чтения сносок; «?» раскрывает определение; доля явки показана `80%`; даты и десятичные в одном формате; «Смотреть как» переживает перезагрузку.  
**N:** нет данных → «—» и подсказка, а не `NaN%`; подсказка на касании и с клавиатуры; `prefers-reduced-motion`; длинный термин переносится; cookie `view_as` повреждена → реальная роль; предпросмотр без доступных пунктов → понятное пояснение.  
**S:** `view_as` не влияет на права и DTO — все проверки по реальной роли (AZ без изменений); cookie без ПД; в подсказках нет персональных данных.

## 9. Acceptance criteria

- [ ] В `ru/*.json` нет стоп-слов из §4 п. 5 — исход: vitest-тест словаря.
- [ ] «Явка» в таблицах — `80%`, не `0.8%` — исход: тест форматтера и таблиц.
- [ ] `TermHint` открывается мышью, касанием и клавиатурой, закрывается Esc — исход: тест компонента, секция Lab.
- [ ] `view_as` переживает перезагрузку и не меняет доступ — исход: тест чтения cookie + тест доступа реальной роли.
- [ ] Каждое значение `AUDIT_ENTITY_TYPE` / `AUDIT_ACTION` имеет подпись ru и en; в props клиентских компонентов нет функций — исход: тест паритета, `assertSerializableMessages`.
