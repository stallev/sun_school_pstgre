## 1. Purpose

Четвёртый аудит (2026-11-13) показал, что главная проблема — не отсутствие подсказок, а **вёрстка**: на 1024 px раскрытый сайдбар (288 px) оставляет контенту ~647 px, из-за чего таблицы получают внутренний горизонтальный скролл, заголовки сжимаются в столбик, имена учеников обрезаются (R-1, D-01…D-03, D-22); отступы берутся из пяти-шести случайных значений (4,5 / 6,75 / 9 / 13,5 px); поля по 45 px раздувают формы; карточки в сетках растягиваются на высоту соседа и оставляют пустоту. Нужно одно решение для оболочки, интервалов, полей и «воздуха», чтобы фаза P29 не правила экраны по одному.

## 2. Scope / Out of scope

**В scope:** граница раскрытого сайдбара; токены интервалов и запрет «сырых» отступов в product-коде; высоты полей и интерактивных элементов; сетка форм; правило «широкое содержимое прокручивается внутри обёртки»; таблицы → карточки; правила «воздуха»; правила размещения значка «?» (уточнение UX-03 D-19).  
**Вне scope:** палитра и контраст (UX-03 §4–§5); набор пунктов меню (UX-02 §5); маршруты ([`canonical_routes.md`](../../design/canonical_routes.md) не меняется); права и данные; копирайт сверх критичных правок (U-01…U-12 — задачи фазы, не решение ADR); печатная ведомость, роль «учитель» и родительский кабинет (не покрыты аудитом).

## 3. Context

- Корень `html { font-size: 112.5% }` (18 px). Tailwind-значения в `rem`, поэтому `gap-1` = 4,5 px, `gap-2` = 9 px, `gap-3` = 13,5 px, `h-9` = 40,5 px, `h-10` = 45 px, `h-11` = 49,5 px. Аудит измерял px при корне 18.
- ADR-017 включил раскрытый сайдбар `w-64` (16rem = 288 px) с `lg` (1024). Макеты рассчитаны на контент ≥ 960 px.
- UX-03 D-9: поле `h-10` (45 px), `compact` `h-9` (40,5 px); D-14: кнопка `h-9`; `size="field"` `h-10`. Кнопка и поле на одной линии расходятся.
- UX-03 §7 не содержит шкалы интервалов; в коде — произвольные `gap-*`.
- `TermLabel` (ADR-020) в ряде мест ломает вёрстку (дубль подписи и кнопки, двоеточие после значка, плейсхолдер `{term}` в `aria-label`, значок раздувает `line-height`).

## 4. Decision

### 4.1. R-1 — оболочка по ширине (поправка к ADR-017 п. 2)

| Ширина | Сайдбар |
|--------|---------|
| `< lg` (< 1024) | drawer (без изменений) |
| `lg` (1024–1279) | **rail `4rem` по умолчанию**; cookie `sidebar_collapsed` приоритетнее умолчания (`0` — пользователь явно раскрыл, `1` — свёрнут) |
| `≥ xl` (≥ 1280) | развёрнут `16rem` по умолчанию; cookie приоритетнее |

Cookie без значения (первый визит) на `lg` → rail, на `xl+` → развёрнут. Сервер рендерит нужную сетку из cookie, а при её отсутствии — безопасный вариант для `lg` через CSS-классы (`lg:w-16 xl:w-64`), без мигания и без чтения ширины на сервере. Кнопка сворачивания остаётся; явный выбор пользователя на `lg` («развернуть») сохраняется в cookie и уважается. Критерий: на 1024 px (rail) под контент ≥ 900 px.

### 4.2. Шкала интервалов (токены)

Токены задаются в `:root` в `rem` как `px/18`, чтобы совпадать со значениями аудита (раздел 3.3) **при корне 18 px** и расти вместе с шрифтом, и мапятся в `@theme inline` как `--spacing-*` (утилиты `gap-hint`, `gap-chip`, `p-card`, `py-section`, `px-page`…).

| Токен | rem | px при корне 18 | Где |
|-------|-----|-----------------|-----|
| `--space-hint` | 0.45rem | 8,1 | слово → значок «?», иконка → текст в кнопке |
| `--space-label` | 0.35rem | 6,3 | подпись → поле |
| `--space-chip` | 0.45rem | 8,1 | цепочка чипов/табов/кнопок, `gap` по обеим осям |
| `--space-stack` | 0.9rem | 16,2 | шаг между блоками внутри карточки, между полями формы |
| `--space-card` | 0.9rem (mobile) / 1.35rem (`md+`) | 16,2 / 24,3 | карточка → карточка, внутренний `padding` карточки |
| `--space-section` | 1.8rem (mobile) / 2.2rem (`md+`) | 32,4 / 39,6 | секция → секция страницы |
| `--space-page-x` | 0.9 / 1.35 / 1.8rem | 16,2 / 24,3 / 32,4 | боковой отступ контейнера: mobile / `md` / `lg+` |

**Корректировка относительно отчёта (по UX-03):** отчёт перечисляет px, Tailwind-шкала даёт 9 px для `gap-2`. Чтобы не плодить второй набор «почти 8 px», значения даны в `rem` и совпадают с отчётом в пределах 0,4 px; критерий «зазор ≥ 8 px» выполняется (8,1). Прежний `px-4 sm:px-6 lg:px-8` у контейнера (UX-03 §7: 18 / 27 / 36 px) заменяется на `--space-page-x` (16,2 / 24,3 / 32,4) — фиксируется как поправка к §7.

**ESLint-правило** (`no-restricted-syntax` по `className` / `cn()` / `cva()`) запрещает в product-коде (`apps/web/src/components/**`, `app/**`, кроме `components/ui/**` и `design-lab/**`) утилиты `gap-*`, `gap-x-*`, `gap-y-*`, `space-x-*`, `space-y-*`, `p-*`, `px-*`, `py-*`, `pt/pb/pl/pr-*` с числовыми значениями из шкалы Tailwind (`gap-1`, `gap-1.5`, `gap-2`, `gap-3`, `p-4` и т. п.); разрешены токены (`gap-chip`, `p-card`, …), `0`, `px`, `auto`, а также `gap-4` / `gap-6` только как алиасы токенов, если команда их так определит в `@theme` (по умолчанию — нет). Исключения — `components/ui/**` (там значения часть рецепта) и места с комментарием `// eslint-disable-next-line … -- причина`.

### 4.3. Высоты полей и интерактивных элементов (поправка к UX-03 D-9, D-14)

| Размер | Класс | px при корне 18 | Где |
|--------|-------|-----------------|-----|
| Поле (`Input`, `Select`, `DateField`) | `h-9` | 40,5 (≈ 40) | обычные формы |
| Поле компактное | `h-8` | 36 | строки фильтров, таблицы |
| Кнопка / чип / сегмент | `h-9` (как сейчас) или `h-8` рядом с компактным полем | 40,5 / 36 | кнопка рядом с полем **наследует высоту поля** |
| `touch` | `h-11` | 49,5 (цель ≥ 44) | основное действие / нижняя панель на `< md` |

- Прежний `default` поля `h-10` (45 px) и `size="field"` (`h-10`) **упраздняются**; шкала D-9: `--control-h` = `h-9`, `--control-h-compact` = `h-8`, `--control-h-touch` = `h-11`.
- **Минимальный размер интерактивного элемента — 36 px (`h-8`).** Ссылка-кнопка, чип, таб — `min-h-8` минимум; внутри текста ссылки исключены. Отчёт назвал 36 px «`h-9`», но при корне 18 `h-9` = 40,5; контракт использует **реальные px и классы**: 36 px = `h-8`.
- Зазор в цепочке чипов/табов/кнопок — `--space-chip` (≥ 8 px) по обеим осям; между цепочками — `--space-stack`.

### 4.4. Форма — 12-колоночная сетка

Все формы (`FormSection`, фильтры, `/lessons/new`, `/audit`) — `grid grid-cols-12 gap-x-stack gap-y-stack`. Подпись поля — фиксированной высоты (`min-h-5`, одна строка), значок «?» внутри подписи `inline`, высотой `1em`, `align-middle`, **не меняет высоту подписи**. Кнопка в ряду с полем — одной высоты с ним. Верхние края полей в одном ряду совпадают ±1 px (скриптовый замер входит в Acceptance страницы). Поля — `w-full` своей колонки; правый край ряда общий.

### 4.5. «Широкое содержимое» и таблицы → карточки

1. Таблицы, шкалы, графики, `<pre>` — в обёртке `overflow-x-auto min-w-0` (и `max-w-full`); страница не растягивается: `document.scrollingElement.scrollWidth == innerWidth` на 360 / 768 / 1024 / 1440.
2. Flex-родитель широкого содержимого — `min-w-0`; заголовок страницы **не сжимается из-за панели действий**: панель переносится под заголовок, пока ширина контента < 960 px (`flex-wrap`, заголовок `basis-full`).
3. Журнал и списки (`/audit`, `/groups/[id]/points`, `/users`) до `lg` — **карточки**; от `lg` — таблица. Таблица журнала помещается без внутреннего скролла от `xl` (`table-layout: fixed`, доли колонок, перенос по словам). «Техническая запись» — `whitespace-pre-wrap break-all`, `max-h` с прокруткой по Y.
4. Данные пользователя (имя ученика) в заголовках **не обрезаются** (`truncate` запрещён); `truncate` — только в плотных списках с `title`.
5. Двухколоночная проверка ДЗ — с `xl` (≥ 1280); ниже — одна колонка со списком учеников в раскрывающемся блоке. Шкала теста (9 кнопок) — `SegmentedControl` с переносом на 2 ряда (0–4, 5–8) на ширинах < `xl`.

### 4.6. Правила против «воздуха»

1. Сетки карточек — `items-start` (запрет растягивания на высоту соседа).
2. Чекбоксы и чипы — в строку с переносом (`flex-wrap gap-x-stack gap-y-chip`), шаг между пунктами ≤ 36 px; вертикальный список чекбоксов с шагом ≥ 40 px запрещён.
3. Двухколоночная раскладка, где одна колонка пуста на > 50 % высоты, запрещена: один столбец до `xl`, на `xl+` — 8/4 с `sticky` правой.
4. Вторичные кнопки — по ширине содержимого (`w-auto`), не `w-full` на `md+`.
5. `padding` карточки — `--space-card`; пустое состояние — ≤ 24 px; строка метрики в карточке — компактная.
6. Acceptance: у карточки с одним блоком доля пустоты по вертикали ≤ 30 %.

### 4.7. Правила значка «?» (уточнение UX-03 D-19)

1. Один смысл — один раз на экран: значок живёт в шапке таблицы или у первой карточки, не в каждой строке и не в каждой карточке списка.
2. Значок стоит **после слова**, которое объясняет; не после значения, кнопки, двоеточия.
3. `TermLabel` не добавляет двоеточий; значок не меняет высоту строки; не входит в размер кнопки и **не стоит внутри кнопки**.
4. Нет дубля подписи и действия («Закрыть год ?» + «Закрыть год») — подпись заменяется заголовком секции, кнопка — глаголом с объектом.
5. Тест словаря: ни в `hint`/`term`, ни в `aria-label` нет `{` и `}` (плейсхолдер не подставлен).
6. `aria-label` значка — «Что значит «термин»?» с подставленным термином.

## 5. Rejected alternatives

| Вариант | Почему отклонён |
|---------|-----------------|
| Оставить раскрытый сайдбар на `lg`, сузить до 224 px | Контент 800 px остаётся недостаточным для таблиц журнала и школы; теряется критерий ≥ 900 px |
| Брейкпоинт сайдбара `2xl` (1536) | На 1280–1535 раскрытый сайдбар не нужен при rail, но 1280 — типичный ноутбук; `xl` даёт контент ≥ 900 |
| Токены только в px (`--space-hint: 8px`) | Не растут с шрифтом; расходятся с остальным rem-кодом |
| Токены = «круглые» значения Tailwind (`gap-2` = 9 px) без своего слоя | Нет запрета «сырых» значений, дрейф возвращается; нельзя проверить правилом |
| Поле 45 px, как сейчас | Формы раздуты (фильтры `/audit` 385 px); кнопка и поле расходятся |
| Поле 36 px везде | Хуже для сенсорного ввода и читаемости 18-px текста; 36 оставлен как компактное |
| `size="field"` оставить | Второй размер кнопки рядом с полем — источник рассинхрона; кнопка наследует высоту поля |
| Внутренний скролл таблицы журнала, исправить только шапку | Обрезанная колонка «Детали» — главная информация строки |
| Правило «воздуха» только в ревью | Не воспроизводится; нужны измеримые критерии (доля пустоты, шаг списка) |
| `title`/tooltip вместо значка | Не работает на сенсорных экранах (ADR-018 отверг) |

- `ui-design-system-shadcn.mdc` и `ui-mobile-first.mdc` (tier-копия и корень) → правила Controls / Layout / Spacing; `rules:sync`.
- Lab (`design_system_lab_spec.md`) → секции «Spacing scale», «Field heights», «TermLabel (позиция, без двоеточий)», «Responsive table → cards».
- `responsive_navigation_contract.md` (UX-02) и `global_shell_spec.md` → граница `xl`.
- Все product-экраны переводятся на токены (задачи P29); ESLint-правило запрещает новые «сырые» отступы.
- Прототип — в соответствие (Change log).
- Маршруты, права, данные не меняются.

## 7. Paths (H / N / S)

**H:** на 1024 px — rail и контент ≥ 900 px; на 360/768/1024/1440 нет горизонтального скролла страницы; `/audit` ≥ 1280 без внутреннего скролла; поля 40,5 / 36 px; зазор в цепочке чипов ≥ 8 px; верхние края полей в ряду ±1 px.  
**N:** cookie `sidebar_collapsed` нет или повреждена → умолчание по ширине; длинное имя ученика → перенос, не обрезка; нулевые/пустые данные → пустое состояние ≤ 24 px; `reduced-motion` → без анимации ширины сайдбара.  
**S:** n/a — вёрстка и токены; cookie — UI-предпочтение без ПД (как в ADR-017); права и набор пунктов решает сервер.

## 9. Acceptance criteria

- [ ] `scrollWidth == innerWidth` страницы на 360 / 768 / 1024 / 1440 для всех экранов аудита — исход: скриптовый замер.
- [ ] Внутреннего скролла (`scrollWidth > clientWidth` у обёртки) нет на `/audit` ≥ 1280 и на `/school`, `/analytics` при 1024 — исход: замер.
- [ ] На 1024 px под контентом ≥ 900 px; cookie приоритетнее умолчания — исход: тест `app-shell` + замер.
- [ ] Высота поля 40,5 ±1 / компактного 36 ±1 px; кнопка рядом с полем той же высоты — исход: тесты компонентов + замер.
- [ ] Зазор в цепочке чипов ≥ 8 px; верхние края полей в ряду ±1 px — исход: замер.
- [ ] Доля пустоты карточки с одним блоком ≤ 30 %; шаг списка чекбоксов ≤ 36 px — исход: замер.
- [ ] В `aria-label` и словаре нет `{` `}` — исход: тест.
- [ ] ESLint блокирует «сырые» `gap-*`/`space-*`/`p-*` в product-коде — исход: тест правила.
