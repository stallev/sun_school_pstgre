# ADR-012 — Волна 1: достижения и штрафы

**Тип:** ADR  
**Статус:** ACCEPTED  
**Версия:** 1.0  
**Дата:** 2026-10-22

**Зависит от:** [`achievements_spec.md`](../../my_specs/achievements_spec.md) §1–§10, [`post_mvp_deferrals.md`](../01_product_scope/post_mvp_deferrals.md) §3.1, [`adr_005_schema_complete_post_mvp_tables.md`](./adr_005_schema_complete_post_mvp_tables.md), [`database_schema_v1.md`](../03_data_model/database_schema_v1.md) §4, §6, [`bricks_ledger_contract.md`](../../implementation/mvp/contracts/bricks_ledger_contract.md) §3

## 1. Purpose

Зафиксировать, как волна 1 (достижения и штрафы) входит в приложение, не ломая MVP при выключенном флаге, и как интерфейс этой волны сверяется с прототипом.

## 2. Scope / Out of scope

**В scope:** флаг `features.achievements`, пересчёт, формула «набрано», режим группы для уже существующих групп, обязательная сверка UI с прототипом.  
**Вне scope:** роль `parent`, экраны `/child` и `/family`, еженедельный дайджест, достижение `practice`, голосовая проверка (волны 2 и 3).

## 3. Context

Таблицы волны 1 и ключ `features.achievements = false` уже есть (ADR-005). Стартовый каталог загружается сидом и спит. Interim-спека описывает правила; канонического контракта и фазы до этого ADR не было.

Спека §7.2 требует интерактивную транзакцию и блокировку на ученика и отдельно отмечает, что HTTP-режим Neon для этого не подходит. ORM уже выбран: Prisma v7 с адаптером `pg`.

Колонка `grade_settings.achievements_enabled` в схеме по умолчанию `false` (таблицы спали). ДС-14 говорит: режим по умолчанию включён, а уроки периода выключения — пропуск, чтобы включение не выдало пачку наград за прошлое.

Владелец 2026-10-22: переходить к проектированию волны 1; при реализации UI — полное соответствие стилям прототипа.

## 4. Decision

| # | Решение |
|---|---------|
| 1 | Волна 1 реализуется за флагом `features.achievements`. Пока флаг выключен, `saveChecked`, `correctCheck`, `completeLessonCheck` и `closeYear` не вызывают пересчёт; экраны и блоки достижений не показываются; «набрано» считается как в MVP (бонус и штрафы = 0). Отказ мутации при выключенном флаге — на сервере, код `ACHIEVEMENT_FLAG_OFF` |
| 2 | Включение флага в prod — действие владельца после условия [`post_mvp_deferrals.md`](../01_product_scope/post_mvp_deferrals.md) §3.1: MVP у реальных пользователей и зелёные тесты `evaluate` (§7.3 спеки). Проектирование и код за флагом этому условию не противоречат |
| 3 | Пересчёт — чистая функция `evaluate` в `@sunschool/domain`. Запись выдач — в интерактивной транзакции Prisma (`pg` adapter) с блокировкой на ученика. HTTP-batch Neon для пересчёта запрещён |
| 4 | «Набрано» при включённом флаге = очки проверок + баллы неотзванных выдач − баллы действующих штрафов. Строка `brick_ledger` при выдаче достижения или штрафа не создаётся. Журнал кирпичиков остаётся только добавлением |
| 5 | Выдача — неизменяемый факт. Отзыв снимает баллы и не освобождает доказательства. Штраф не редактируется: его снимают |
| 6 | Режим группы. Группа, созданная при выключенном флаге (`achievements_enabled = false`, периодов выключения нет), после включения флага остаётся выключенной, пока teacher своей группы или admin не включит режим. Уроки до этого включения — пропуск. Группа, созданная при включённом флаге, получает режим включённым (ДС-14). Копирование настроек на новый год сохраняет текущее значение |
| 7 | UI волны обязан совпадать с прототипом [`sunday_school_prototype.html`](../../prototypes/sunday_school_prototype.html): структура и порядок секций, тексты ru, кегль, насыщенность, токены `penalty` и `tier-1..3`. Расхождение чинится в коде. Это критерий приёмки каждого UI-CU фазы P12 (правило `ui-prototype-fidelity`) |
| 8 | Каталог §9 спеки заново не сеется. Достижение `practice` остаётся неактивным до волны 3. Выдачи и штрафы в prod-seed не создаются |
| 9 | Семьи, голосовые попытки и роль `parent` код волны 1 не читает и не пишет (PKG-03, сужение — только таблицы достижений и штрафов) |

## 5. Rejected alternatives

| Альтернатива | Почему отклонена |
|--------------|------------------|
| Считать достижения на лету, без таблицы выдач | Выдача начисляет кирпичики; исчезновение после правки разойдётся с «набрано» (спека §7.4) |
| Писать бонус строкой `brick_ledger` | Журнал только добавление; отзыв пришлось бы компенсировать второй записью и путать с ручной выдачей кирпичиков |
| Включить режим всем существующим группам при включении флага | Пересчёт выдал бы награды за прошлое, от чего защищает ДС-14 |
| HTTP-batch Neon для пересчёта | Нет интерактивной транзакции и блокировки на ученика (спека §7.2) |
| Сверять UI «примерно по токенам» | Владелец требует полное соответствие стилям прототипа |

## 6. Consequences

- Контракт и экранная спецификация волны 1, фаза P12.
- Формула «набрано» в контракте кирпичиков зависит от флага.
- Строки прав AZ-52…AZ-57 и action-коды журнала.
- PKG-03 разрешает код P12 для таблиц достижений и штрафов.
- UI-CU не коммитится без строки `UI-verify: …, расхождений 0`.

## 7. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Флаг включён, режим группы включён, проверка урока завершена | `evaluate` записал новые выдачи; учитель видит «кого отметить» |
| **H** | Флаг выключен, учитель завершает проверку | Пересчёта нет, блоки достижений скрыты, «набрано» без бонуса |
| **N** | Повторный пересчёт тех же фактов | Новых выдач нет |
| **S** | Teacher открывает `/achievements` или выдачу чужой группы | 403 на каталог; чужая группа — 404 |
| **S** | Клиент передаёт баллы выше каталога | Сервер отклоняет; снимок правила — с сервера |
| **Drift** | MVP-код читает `family` или `recitation_attempt` | Review и PKG-03 |

## 9. Acceptance criteria

- [ ] При выключенном флаге завершение проверки не пишет `achievement_award` — исход: тест use-case.
- [ ] `evaluate` идемпотентна на одних фактах — исход: тест §7.3 спеки.
- [ ] «Набрано» при флаге = проверки + неотзванные выдачи − действующие штрафы, без новой строки `brick_ledger` — исход: тест баланса.
- [ ] Группа, созданная до флага, после включения флага не получает автовыдачи, пока режим не включён — исход: тест режима.
- [ ] UI-CU P12 содержит trace `UI-verify: …, расхождений 0` — исход: описание фазы.
