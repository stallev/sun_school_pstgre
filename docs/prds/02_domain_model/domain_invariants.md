## 1. Purpose

**Неизменяемые правила** домена: что система обязана гарантировать независимо от UI и транспорта. Расширяют пять инвариантов из `project-context.mdc` и служат опорой для тестов `@sunschool/domain`, ограничений БД и review. Читают: авторы контрактов W8, исполнители, reviewer.

## 2. Scope / Out of scope

**В scope:** правила MVP, границы пакетов, защиты от drift.  
**Вне scope:** матрица прав (`authorization_matrix`, W5-02), копирайт и состояния экранов (UX), выбор индексов (W6).

## 3. Definitions

| Префикс | Значение |

| `INV-NN` | Доменный инвариант (этот документ) |

## 4. Инварианты

Колонка **Enforcement** — где правило обеспечивается: `DB` (ограничение), `domain` (чистая функция), `DAL` (транзакция), `policy`. **Drift guard** — как обнаружить нарушение. [Контракты W8](../../implementation/mvp/contracts/monorepo_boundaries_contract.md) раскрывают детали и сценарии отказа.

### 4.1 Учебный год и время

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-01** | В школе не более одного `ACTIVE` учебного года (БП-6) | `DB` partial unique (R-1) | тест миграции; проверка в review изменений `academic_year` |
| **INV-02** | Урок создаётся только в `ACTIVE` году, дата урока — в границах года | `domain` + `DAL` (R-3) | unit-тест `createLesson`; контракт [`school_year_and_groups`](../../implementation/mvp/contracts/school_year_and_groups_contract.md), [`homework_check`](../../implementation/mvp/contracts/homework_check_contract.md) |
| **INV-03** | Даты уроков и событий — `date` без времени; моменты (`checked_at`, журнал) — `timestamptz` UTC; «день» для правил (`late`, «Сегодня», просрочка) определяется в **поясе школы** `app_setting.school_timezone` ([ADR-004](../07_governance/adr_004_timezone_scheduling_model.md)) | схема, `domain` (`computeLate`) | тест границ полуночи и перехода на летнее время |

### 4.2 Доступ и роли

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-04** | Права определяются парой «роль + принадлежность ресурса»; одной роли недостаточно: `TEACHER` работает только со своими группами | `policy` на сервере | тест policy на чужую группу → 404/403; [`authorization_matrix.md`](../04_authorization_privacy/authorization_matrix.md) (AZ-D3, AZ-D4, AZ-P6) |
| **INV-05** | Нельзя снять роль `ADMIN` у последнего admin и у самого себя | `DAL` (R-8, блокировка строк) | тест «снять у последнего»; контракт [`access_requests_and_roles`](../../implementation/mvp/contracts/access_requests_and_roles_contract.md) |
| **INV-06** | Пользователь без `ACTIVE` учётной записи не имеет ни одного права, кроме регистрации, ожидания, профиля, запроса на удаление и выхода | `policy`, `proxy.ts` (оптимистично) | тест перенаправлений UX-02 §7 |

### 4.3 Ученики, группы, зачисление

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-07** | У ученика не более одного активного зачисления | `DB` partial unique (R-2) | тест миграции |
| **INV-08** | Зачислить ученика можно только при действующем согласии на данные ребёнка | `DAL` (R-5) | unit-тест `enrollPupil` без согласия → отказ |
| **INV-09** | Перевод между группами сохраняет историю зачислений; отметки ДЗ остаются привязаны к уроку и группе, где выставлены (БП-7) | `domain` (`transferPupil` не изменяет прошлые записи) | тест: после перевода старые проверки видны в старой группе |
| **INV-10** | Кирпичики и баллы считаются по паре «ученик + учебный год», не по группе (БП-11) | `domain` | тест баланса при переводе: остаток не меняется |

### 4.4 Проверка ДЗ и баллы

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-11** | «Не оценивалось» (`NULL`) и «оценено как 0» — разные значения; в средние входит только второе (БП-4) | `DB` (nullable), `domain` | тест `average` с `NULL` и `0` |
| **INV-12** | Присутствие не влияет на баллы, кирпичики и достижения; используется только для посещаемости (БП-10) | `domain` | тест `points` не читает `present` |
| **INV-13** | Баллы записи **заморожены** при выставлении: хранятся `points_total` и `scoring_snapshot`; смена весов действует на новые проверки; правка записи пересчитывает только её (БП-5 вариант А) | `domain` + `DAL` | тест «сменить веса → старые баллы не меняются» |
| **INV-14** | Оценка относится к **дате урока**, а не к дате сдачи; «сдано позже» вычисляется (дата выставления > даты следующего урока группы) и не вводится вручную | `domain` | тест вычисления `late`; запрет поля `late` во входных DTO |
| **INV-15** | Стихи, заданные на уроке N, рассказывают на следующем **обычном** уроке; обзорный урок пропускается (БП-2) | `domain` | тест выбора «стихов к рассказу» через обзорный урок |

### 4.5 Неизменяемые журналы

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-16** | `audit_log` — только добавление; запись не редактируется и не удаляется; исключения — обезличивание (УД-10) и стирание значений о ребёнке (УД-7) | репозиторий без `update`/`delete`; роль БД (R-6) | grep на `update`/`delete` по `audit_log` в review |
| **INV-17** | `brick_ledger` — только добавление; ошибка исправляется компенсирующей записью; единственное исключение — полное удаление данных ребёнка (УД-7) | то же (R-6) | тест отсутствия update-метода |
| **INV-18** | Выдача не превышает остаток на момент выдачи; отрицательный остаток возможен только вследствие уменьшения баллов и виден лишь `TEACHER`/`ADMIN` | `DAL` в транзакции (R-7) | тест параллельных выдач |

### 4.6 Библия и золотые стихи

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-19** | Золотой стих хранится как диапазон в **Синодальной** нумерации; прочие переводы приводятся к ней таблицей `bible_verse_map` (ADR-009) | `domain`, данные карты | проверка скрипта загрузки: суммы по главам |
| **INV-20** | Текст золотого стиха собирается из стихов диапазона **в переводе группы**; если стиха нет — урок не сохраняется, форма показывает недостающие (ПБ-5) | `domain` (R-9) | тест `buildVerseText` с пропуском |
| **INV-21** | Ссылка у использованного золотого стиха не меняется; правка создаёт новый стих | `DAL` | тест запрета правки при наличии `lesson_golden_verse` |

### 4.7 Персональные данные

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-22** | Данные ребёнка по запросу опекуна удаляются **полностью**; данные взрослого — удаляются или обезличиваются (УД-7); выполнение — только по запросу, с планом и подтверждением | процедура `executeDeletion` (`DAL`) | тест плана удаления; контракт [`deletion_requests`](../../implementation/mvp/contracts/deletion_requests_contract.md) |
| **INV-23** | Журналы хранят **ссылки** на пользователя и ученика, имена подставляются при показе; поля «старое/новое значение» не содержат ПД | `domain` (сериализация записи журнала) | тест: очистка пользователя не требует правки журнала |

### 4.8 Окружения и фоновые операции

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **INV-24** | `APP_ENV` сверяется со строкой подключения при старте; `seed:dev` отказывается работать вне `dev`; фейковые данные не попадают в prod, реальные — в dev (ОК-1, ОК-4) | старт приложения, скрипт | тест: prod-URL + `seed:dev` → отказ |
| **INV-25** | В MVP нет фоновых задач и cron; просроченные записи (регистрации > 30 дней) очищаются **лениво** при обращении; срок запроса на удаление — вычисляемая подсветка, статус не меняется сам | `domain` (`purgeExpiredRegistration` вызывается из use-case) | grep: нет cron-маршрутов и `vercel.json` `crons` |

### 4.9 Границы пакетов

| ID | Rule | Enforcement | Drift guard |
|----|------|-------------|-------------|
| **PKG-01** | `@sunschool/domain` — чистые правила: без Next, Prisma, `process.env` | ESLint boundaries | `npm run lint` |
| **PKG-02** | `@sunschool/policy-server` не импортируется в `proxy.ts`; `proxy.ts` использует только `policy-edge` и `auth.config.ts` | ESLint boundaries | review + lint |
| **PKG-03** | Таблицы и код post-MVP не являются зависимостью MVP; MVP-таблицы ссылаются на post-MVP только `NULL`-able (С-1, С-2) | схема | сверка FK при изменении схемы |

## 5. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Любая допустимая операция домена | Инварианты сохраняются; тест `domain` зелёный |
| **N** | Операция нарушает инвариант | Отказ с кодом из `@sunschool/domain`; данные не меняются |
| **S** | INV-04…INV-06, INV-22, INV-23 | Нарушение — security blocker в review (`reviewer`, T3) |
| **Races** | INV-01, INV-05, INV-07, INV-18 | Ограничение БД или блокировка строк даёт один успех |
| **Drift** | Код расходится с правилами | Drift guard колонки §4 ловит в CI / review |

## 6. Acceptance criteria

- [ ] Каждый инвариант имеет источник, enforcement и drift guard — исход: нет пустых ячеек в §4.
- [ ] Все пять инвариантов `project-context.mdc` отражены (§3) — исход: сопоставление без пропусков.
- [ ] Инварианты не противоречат `lifecycle_models.md` — исход: переходы §5 lifecycles не нарушают INV-01…INV-18.
- [ ] Каждое правило, обеспечиваемое БД, есть в `database_schema_v1.md` §7 — исход: R-1…R-9 покрывают INV-01, INV-05, INV-07, INV-16…INV-18.
