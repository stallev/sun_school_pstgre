## 1. Purpose

Единые правила форм MVP: подписи, ошибки полей, фокус, ожидание, подтверждения, конфликты. Читают: авторы specs W9 и контрактов W8, исполнители UI-фаз, `reviewer`.

## 2. Scope / Out of scope

**В scope:** все формы и диалоги с вводом в `apps/web`, поведение клиента и сервера при валидации.  
**Вне scope:** тексты сообщений (словари ADR-008), визуальные токены ([`visual_identity_contract.md`](./visual_identity_contract.md)), состояния страниц ([`ui_states_contract.md`](./ui_states_contract.md)), контракты мутаций (W8).

## 3. Definitions

| Термин | Значение |
|--------|----------|
| Field error | Ошибка конкретного поля (формат, диапазон, обязательность) |
| Form error | Ошибка отправки без привязки к полю (конфликт, нет прав, сбой) |
| Server validation | Проверка на сервере по правилам `@sunschool/domain` — **единственный источник истины** |
| Class B | Форма, чувствительная к iOS Safari-транспорту отправки (`ios-safari-mutation-transport`) |
| Code | Код отказа `MutationErrorCode` из `@sunschool/domain` (`VALIDATION`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `UNAUTHORIZED`) |

## 4. Правила

| ID | Правило |
|----|---------|
| **F1** | У каждого поля есть видимая `<label>` (не placeholder). Обязательные поля помечены текстом «обязательно» в подписи, не только `*` и цветом |
| **F2** | Правила валидации описаны один раз в `@sunschool/domain` (Zod-схемы). Клиент использует их для подсказки, **сервер проверяет всегда** независимо от клиента |
| **F3** | Ошибка поля — под полем, `id` ошибки связан через `aria-describedby`, у поля `aria-invalid="true"`; текст — ключ словаря, не код. Цвет `danger` + иконка + текст (контраст: `danger` на `danger-soft` недопустим для текста, visual_identity §контраст) |
| **F4** | После отправки с ошибками фокус переходит на **первое невалидное поле**; для форм длиннее экрана сверху показывается сводка (`role="alert"`) со ссылками на поля |
| **F5** | Валидация при **потере фокуса** и при отправке; ошибка исчезает при исправлении (не раньше, чем поле становится валидным). Не показывать ошибку на нетронутом поле |
| **F6** | Введённые значения при ошибке **не теряются**. React 19 сбрасывает неуправляемые поля после action — сервер возвращает введённое в `state`, поля читают `defaultValue` (или поле управляемое) |
| **F7** | Отправка: `disabled={pending}`, `aria-busy={pending}`, подпись-герундий («Сохраняем…»), повторная отправка заблокирована; результат — toast 2000 ms (`ui-toast-mutations`), ошибка — на месте **и** toast |
| **F8** | Кнопка отправки есть всегда и не скрыта в sticky-панели мимо клавиатуры; основное действие одно (`cobalt-ink`), второстепенные — контурные; в мобильной форме кнопки внизу в зоне большого пальца, цель ≥ 44 px |
| **F9** | Поля: `border-muted` (D-7, контраст ≥ 3:1), высота ≥ 40 px, `font-size ≥ 16 px` на мобильных (без автозума iOS), подходящие `inputmode`, `autocomplete`, `enterkeyhint` |
| **F10** | Формы Class B (отправка с iOS Safari, критичные мутации: проверка ДЗ, кирпичики, регистрация) используют транспорт по `ios-safari-mutation-transport`; отдельные тесты не обязательны на lean, но путь отмечается в спецификации экрана |
| **F11** | ПД не попадают в URL, `localStorage` и логи; черновики хранятся только в состоянии формы (исключение — черновик проверки ДЗ, §7.2) |
| **F12** | Серверный отказ по правам (`FORBIDDEN`) не раскрывает причину; `NOT_FOUND` одинаков для чужого и отсутствующего (AZ-D4) |

## 5. Поля и ограничения домена

| Поле | Правило | Источник |
|------|---------|----------|
| Фамилия, имя | Обязательны; буквы (Unicode), пробел, дефис, апостроф; 1–50 символов; пробелы по краям обрезаются | РГ-3 |
| Отчество | Необязательно; те же символы; ≤ 50 | РГ-3 |
| Согласие на обработку ПД | Чекбокс **не отмечен** по умолчанию; без него кнопка отправки неактивна и сервер отказывает | РГ-2 |
| Email, Telegram-имя | Из провайдера, только чтение | ADR-003 |
| Дата урока / события | `date`; в границах активного года; пояс школы для «сегодня» | INV-02, ADR-004 |
| Баллы теста, тетради | Целое 0–10 или «не оценивалось» (`NULL`, пустой выбор «—») | БП-4, INV-11 |
| Оценка стиха | Выбор 0 / 1 / 2 или «—» | БП-3 |
| Спевка | Переключатель; `false` ≠ «не оценивалось» (по настройкам группы) | БП-3 |
| Присутствие | Переключатель; не влияет на баллы | INV-12 |
| Кирпичики | Целое ≠ 0; выдача ≤ остатка; минус — только с обязательным примечанием | R-7, INV-18 |
| Причина | Обязательна: отклонение заявки, отклонение запроса удаления, корректировка закрытого года (admin), снятие штрафа/отзыв (post-MVP) | §2.4, УД-6, БП-12 |
| Комментарий | Необязательно; до 500 символов (по умолчанию) | БП-12 |
| Золотой стих | Книга → глава → стих «с» (и «по» ≥ «с»); диапазон существует в переводе группы; недостающие стихи — списком | ПБ-5, INV-20 |
| Роли и группы при одобрении | ≥ 1 роль; для `TEACHER` ≥ 1 группа на активный год; `PARENT` недоступна | §2.4, AZ-P3 |
| Язык интерфейса, пояс | Выбор из списка; пояс — IANA с поиском; проверка списком | ADR-004, ADR-008 |
| Язык группы | `RU` / `EN`; `EN` недоступен, пока перевод не `READY` | ЯГ-3 |

|-------|-----|---------------|---------------------------------------------------------------|
| Регистрация | `/register` | ФИО, согласие | `CONFLICT` (повторная отправка), устаревшая версия согласия |
| Профиль | `/profile` | ФИО | — |
| Привязка / отвязка входа | `/profile` | провайдер (выбор) | `AUTH_LINK_CONFLICT`, `AUTH_LAST_IDENTITY` |

| Роли пользователя | `/users/[userId]` | роли, группы | последний admin, снять с себя (AZ-P1, AZ-P2) |

| Бумажное согласие | `/people` (диалог) | опекун, дата, версия, где оригинал | — |
| Зачисление / перевод / исключение | `/people`, `/group` | ученик, группа, дата | нет согласия (R-5), активное зачисление (INV-07) |
| Урок | `/lessons/new`, `/lessons/[id]/edit` | тема, дата, тип, стихи, тест, ведущий | вне года, год закрыт, нет стиха в переводе (R-9), ведущий не назначен (R-4) |
| Проверка ДЗ | `/lessons/[id]/check` | присутствие, тетрадь, тест, стихи, спевка, комментарий | год закрыт, `CONFLICT` (другая правка) |
| Корректировка проверенного | `/lessons/[id]/check`, таблица | поле, значение, причина | год закрыт без причины (admin), teacher в закрытом году |
| Кирпичики | `/bricks` | ученик, количество, примечание | превышение остатка, ноль, минус без примечания |
| Событие календаря | `/calendar` | дата, тип, название, описание | год закрыт для teacher |
| Запрос на удаление | `/profile` | причина (необязательно) | уже есть открытый запрос (УД-2) |

| Настройки приложения | `/settings` | язык, часовой пояс | неизвестный пояс |

## 7. Поведение

### 7.1 Подтверждения

| Случай | Паттерн |
|--------|---------|
| Необратимое / массовое / затрагивает ПД (выполнение удаления, исключение из группы, отключение доступа) | Диалог: что произойдёт (удалено / обезличено, УД-2), основная кнопка `danger`, фокус по умолчанию на «Отмена», Esc закрывает |
| Обратимое и быстрое (переключатель, сохранение) | Без диалога; результат — toast |
| Причина обязательна | Поле в том же диалоге; кнопка неактивна до ввода (серверная проверка остаётся) |
| Повтор после ошибки | Диалог остаётся открытым, введённое сохранено, ошибка внутри |

Ввод слова-подтверждения не требуется, **кроме выполнения запроса на удаление** ПД (`executeDeletion`, УД-8): там обязателен ввод слова из словаря и подтверждение плана ([`deletion_requests_contract.md`](../implementation/mvp/contracts/deletion_requests_contract.md) §5.4).

### 7.2 Проверка ДЗ (длинная форма)

| Правило | Поведение |
|---------|-----------|
| Сохранение по ученику | Кнопка «Сохранить и далее»; частичное сохранение допустимо (D5, ui_states) |
| «Не оценивалось» | Поле остаётся пустым («—»); `NULL`, не `0` (INV-11); в среднее не входит |
| Несохранённые изменения | Индикатор в шапке; предупреждение при уходе со страницы (`beforeunload`) и при переходе к другому ученику без сохранения |
| Параллельная правка | Сервер отвечает `CONFLICT` при изменении записи другим пользователем после загрузки формы; сообщение «Запись изменилась — обновите» и кнопка «Загрузить актуальное», локальные правки показываются для переноса |
| Повторная отправка | Идемпотентна: повтор не создаёт новой записи и не удваивает баллы (INV-13) |

### 7.3 Конфликты и гонки

| Ситуация | Код | Поведение |
|----------|-----|-----------|
| Запись изменена другим | `CONFLICT` | F4 + сообщение, данные формы сохранены |
| Двойная отправка (двойной клик, повтор из очереди) | — | Блокировка клиента (F7) и идемпотентность сервера |
| Выдача кирпичиков параллельно | `VALIDATION` (превышение остатка) | Показ актуального остатка, форма сохранена (R-7, INV-18) |
| Заявка уже решена другим admin | `CONFLICT` | Список обновляется, сообщение «Заявка уже обработана» |

## 8. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Пользователь заполняет регистрацию, отмечает согласие | Кнопка активна → отправка → `/pending`, toast |
| **H** | Teacher оставляет поле теста пустым и сохраняет | `NULL`, «—», в среднее не входит |
| **N** | ФИО содержит цифры | Ошибка под полем, фокус на поле, введённое сохранено |
| **N** | Сервер вернул `VALIDATION` для поля, прошедшего клиент | Ошибка на поле (источник — сервер), значения сохранены |
| **N** | Урок в диапазоне стихов без текста в переводе группы | Урок не сохранён, список недостающих стихов (R-9) |
| **N** | Сеть пропала при отправке | Ошибка формы, данные сохранены, «Повторить» |
| **S** | Подмена `userId`/`gradeId` в теле запроса | Игнорируется / `NOT_FOUND`; проверка по сессии (AZ-D4) |
| **S** | Отправка обходит клиентскую валидацию | Сервер отказывает по тем же правилам (F2) |
| **S** | ПД в query-параметре | Запрещено (F11) |
| **a11y** | Скринридер, только клавиатура | Фокус на ошибке, `role="alert"`, закрытие диалога Esc, фокус возвращается на вызвавший элемент |

## 9. Acceptance criteria

- [ ] Каждое поле формы MVP имеет `<label>` и связанную ошибку (`aria-describedby`) — исход: проверка по каталогу §6.
- [ ] Серверная валидация возвращает те же правила, что клиентская (одна схема) — исход: тест схемы в `@sunschool/domain`.
- [ ] После ошибки значения сохранены (в т.ч. неуправляемые поля) — исход: ручной smoke регистрации и урока.
- [ ] Первое невалидное поле получает фокус — исход: ручной шаг.
- [ ] «Не оценивалось» хранится как `NULL`, не 0 — исход: тест `homework_check`.
- [ ] Кнопки опасных диалогов имеют фокус на «Отмена» — исход: ручной шаг.
- [ ] Двойной клик по «Сохранить» не создаёт дубль — исход: тест идемпотентности.

## 12. Agent notes

- Не показывать плейсхолдер вместо подписи; не использовать цвет как единственный признак ошибки.
- Не полагаться на клиентскую валидацию; серверную писать всегда.
- Не сбрасывать введённое при ошибке (учитывать авто-сброс формы React 19).
- Не отправлять ПД в URL; не логировать значения форм.
- Не создавать собственные коды ошибок на call site — только `@sunschool/domain`.
