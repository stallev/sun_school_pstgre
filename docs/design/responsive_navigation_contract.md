## 1. Purpose

Зафиксировать оболочку приложения и навигацию: как меняется раскладка по ширине, какие разделы видит каждая роль, как подсвечивается текущий раздел, и как оболочка ведёт себя при отказе и ограничениях. Читают: авторы `global_shell_spec` (W9-01), исполнитель P01 / P6, reviewer UI.

## 2. Scope / Out of scope

**В scope:** брейкпоинты, шапка, drawer, сайдбар, группы сайдбара, навигация по ролям MVP, бейджи, фокус и клавиатура, перенаправления оболочки.  
**Вне scope:** содержимое экранов (specs W9), визуальные токены ([UX-03](./visual_identity_contract.md)), список маршрутов ([`canonical_routes.md`](./canonical_routes.md)).

## 3. Брейкпоинты и каркас

| Ширина | Раскладка |
|--------|-----------|
| < `lg` (1024 px), baseline 390 px | Кнопка меню в шапке → **drawer** слева; навигации в шапке нет; сайдбара нет |
| ≥ `lg` | Постоянный **сайдбар** слева `w-64` (16rem); drawer и кнопка меню скрыты; в шапке остаётся бренд и меню пользователя (ADR-014 R-8) |
| любая | Контейнер контента `max-w-[1400px]`, отступы `px-4` → `sm:px-6` → `lg:px-8`, выравнивание влево; узкая страница — `PageSection width="form" \| "wide"` (R-4) |

Каркас `(app)`: `header` (`sticky top-0`, высота 56 px, фон `surface/90` с размытием, граница `line`) → на `lg+` сетка `grid-cols-[16rem_minmax(0,1fr)]`: `aside` (сайдбар, `sticky top-14`, высота `calc(100dvh - 3.5rem)`, собственная прокрутка, `border-r border-line bg-surface`) и `main#main` (`tabindex="-1"`, нижний отступ `pb-28` на мобильных) → контейнер `#view`. Вне оболочки — группа `(auth)`: `/login`, `/register`, `/pending` без шапки и меню.

Программный фокус `main#main` после перехода **не рисует рамку**: `main:focus:not(:focus-visible) { outline: none }` (UX-03 D-12). Тестовый признак: `getComputedStyle(main).outlineStyle === "none"` сразу после навигации.

Поверхности поверх контента: drawer `w-[min(20rem,86vw)]`, bottom-sheet диалог `max-h-[92dvh]`, toast (на мобильных — сверху `top-16`, на `lg` — снизу `bottom-6`, по центру).

## 4. Шапка

| Область | Содержимое | Правила |
|---------|------------|---------|
| Слева | Кнопка меню (< `lg`), слот бренда | ≥ `lg`: «Воскресная школа» (над сайдбаром, ширина `w-64`, граница справа продолжает линию сайдбара). < `lg`: заголовок текущего экрана и строка «имя · роль». Кнопка: `aria-label`, `aria-expanded`, `aria-controls="drawer"` |
| Центр | — | Навигации в шапке нет (сайдбар на `lg+`, drawer на `< lg`) |
| Справа | Меню пользователя | Пункты меню: «Профиль», «Смотреть как» (переключатель роли — **только при `APP_ENV=dev`**, ОК-5; в prod отсутствует в сборке), «Выйти». Переключатель роли перенесён сюда из шапки (ADR-014 R-8); логика и права не меняются |

## 5. Навигация по ролям (MVP)

Источник — `NAV` прототипа; маршруты — [`canonical_routes.md`](./canonical_routes.md). Группа без маршрута в MVP не показывается.

### 5.1 Teacher

| Пункт | Тип | Маршрут |
|-------|-----|---------|
| Сегодня | пункт | `/today` |
| **Уроки** | группа | «Все уроки» `/lessons`, «Проверка ДЗ» `/check`, «Золотые стихи» `/verses` |
| **Группа** | группа | «Состав группы» `/group`, «Кирпичики» `/bricks`, «Рейтинг» `/rating`, «Календарь» `/calendar` |
| Аналитика | пункт | `/analytics` |

### 5.2 Admin

| Пункт | Тип | Маршрут |
|-------|-----|---------|
| Школа | пункт | `/school` |
| **Аналитика** | группа | «Аналитика групп» `/analytics`, «Рейтинг» `/rating`, «Журнал изменений» `/audit` |
| **Люди** | группа | «Заявки на доступ» `/approvals`, «Пользователи» `/users`, «Ученики и семьи» `/people`, «Запросы на удаление» `/deletions`, «Кирпичики» `/bricks` |
| **Учёба** | группа | «Группы» `/groups`, «Учебный год» `/year`, «Календарь» `/calendar`, «Золотые стихи» `/verses`, «Настройки» `/settings` |

«Достижения и штрафы» (`/achievements`) в прототипе стоит в группе «Учёба»; в MVP **не показывается** (post-MVP, волна 1). Подпись «Ученики и семьи» — только текст пункта `/people`; экранов семьи в MVP нет. «Календарь» и «Кирпичики» добавлены admin по решению владельца 2026-10-10 (прототип обновлён); admin работает с любой группой.

### 5.3 Прочее

| Элемент | Правило |
|---------|---------|
| «Профиль» | В меню пользователя (шапка / низ drawer), всем активным ролям, `/profile` |
| Статусы «Регистрация», «Заявка…», «Отклонена» | Без оболочки: `/register` или `/pending`; на этих экранах **обязательна кнопка «Выйти»**, «Профиль» доступен (решение владельца 2026-10-10) |
| Роль `parent` | В MVP отсутствует; её NAV — референс волны 2 |

### 5.4 Подсветка и бейджи

- Активный пункт — `aria-current="page"`, фон `cobalt-soft`, текст `cobalt-ink`. На `/lessons` (drawer, &lt; `lg`) `aria-current="page"` стоит на «Все уроки», не только на группе «Уроки».
- Подсветка по псевдониму (`NAV_ALIAS`): `lesson`, `lessonForm`, `lessonTable` → «Уроки»; `pupil` → «Аналитика»; `groupEdit` → «Группы»; `userProfile` → «Пользователи»; `family` → «Ученики и семьи».
- Бейдж у группы «Люди» = число заявок на доступ в ожидании + открытых запросов на удаление; у «Заявки» — только заявки. Число скрывается при нуле; видим как текст, не только цвет.

## 6. Поведение

1. **Drawer:** открывается кнопкой; фокус переходит на выбранный пункт роли / первый пункт; Esc и клик по затемнению закрывают; фокус возвращается на кнопку; `body` без прокрутки, пока открыт; закрывается при переходе.
2. **Сайдбар (≥ `lg`):** `<nav aria-label="Основная">` со списками ссылок; группа — подзаголовок (`<h2 class="sr-only">` не требуется, заголовок группы видим: `<p>`/`<span>` с `id`, список `aria-labelledby`), пункты всегда видны, **без раскрытия и без `role="menu"`** (ADR-014 R-8). Одиночный пункт («Школа», «Сегодня») — ссылка без заголовка группы. Порядок групп и пунктов — §5. Текущий пункт — `aria-current="page"`. Табуляция идёт по ссылкам в визуальном порядке; Esc ничего не закрывает. Краткое описание пункта (`desc` в `NAV`) раньше показывалось только в выпадающих панелях и теперь не выводится ни в сайдбаре, ни в drawer.
2a. **Меню пользователя (шапка):** disclosure-кнопка с `aria-expanded` и `aria-controls`, панель `DD_PANEL` со ссылками и кнопками; Esc закрывает и возвращает фокус на кнопку; клик снаружи и уход фокуса закрывают.
3. **Переход между экранами:** прокрутка в начало, фокус на `main`, заголовок документа = «Название экрана — Sunday School».
4. **Диалог:** bottom-sheet, фокус внутри, Esc закрывает, возврат фокуса.
5. **Skip-link** «К содержимому» — первый фокусируемый элемент.
6. **Язык:** язык интерфейса общий (ЛК-7), переключателя в шапке нет; настраивается admin в `/settings`.

## 7. Перенаправление и защита

| Ситуация | Поведение |
|----------|-----------|
| Нет сессии | → `/login` |
| Статус «Регистрация» | любой адрес → `/register` (РГ-1) |
| Статус «Заявка на рассмотрении», «Отклонена» | → `/pending` |
| Активный teacher / admin на `/` | → `/today` / `/school` |
| Роль не подходит маршруту | экран «Нет доступа» с кнопкой «На главную» (403), чужой ресурс — 404; тупиков нет (Zero Dead Ends) |

Состояния экранов — [`ui_states_contract.md`](./ui_states_contract.md) §4 (S4).

`proxy.ts` проверяет сессию и роль по префиксу оптимистично ([ADR-002](../prds/07_governance/adr_002_nextjs_vercel_runtime_policy.md) §3); окончательная проверка — на сервере. **Скрытие пункта меню не является защитой.**

## 8. Paths (H / N / S)

| Путь | Описание | Исход |
|------|----------|-------|
| **H** | Teacher на 390 px открывает меню, выбирает «Проверка ДЗ» | Drawer закрывается, открыт `/check`, пункт «Уроки» подсвечен |
| **H** | Admin на `lg` в сайдбаре видит группу «Люди» с пунктами и нажимает «Заявки на доступ» | Открыт `/approvals`, у группы «Люди» и пункта бейдж с числом заявок, пункт подсвечен |
| **N** | Teacher переходит по прямой ссылке на `/users` | Экран «Нет доступа», навигация teacher остаётся, есть кнопка возврата |
| **N** | Активный год отсутствует | Пункты видны, содержимое показывает пустое состояние с призывом (UX-05) |
| **S** | Роль не имеет пункта | Пункт не рендерится на сервере (не CSS-скрытие) |
| **a11y** | Только клавиатура | Меню, drawer, диалог достижимы и закрываются Esc; фокус не теряется |

## 9. Acceptance criteria

- [ ] Набор пунктов teacher / admin совпадает с §5 и `canonical_routes.md` — исход: каждому пункту соответствует строка маршрута.
- [ ] На 390 px и `md` нет горизонтальной прокрутки; навигация доступна — исход: ручная проверка drawer.
- [ ] На `lg` и выше сайдбар заменяет drawer без перезагрузки, выпадающих панелей навигации нет — исход: переключение ширины, в DOM нет `aria-expanded` у пунктов навигации.
- [ ] Контент рядом с сайдбаром занимает остаток ширины до `max-w-[1400px]`; на 1280 и 1920 px нет пустых полей по центру — исход: замер ширины `#view`.
- [ ] После перехода у `main#main` нет видимой рамки — исход: `outlineStyle === "none"`.
- [ ] Переключатель роли отсутствует при `APP_ENV=prod` — исход: нет в DOM и в бандле prod.
- [ ] Бейдж у «Люди» совпадает со счётчиками заявок и запросов — исход: числа равны данным.

## 12. Agent notes

- Не добавлять пункты меню и роли вне §5; новый маршрут — сначала в `canonical_routes.md`.
